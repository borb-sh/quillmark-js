# Codec

> **Implementation**: `src/lib/core/codec/`

## TL;DR

The bidirectional codec between one content field (`Content`) and one ProseMirror document: decode (content → PM), the transaction lowering (PM → a `ChangeBundle` for `applyChange`), and the USV ↔ PM position map that carries the caret. One field, one PM doc; the VisualEditor composes many. Markdown is not in this loop: it is an edge codec (§Markdown at the edges), never the edit representation.

Grounds on quillmark's `Content` model and its WASM edit surface (canon: quillmark `prose/canon/DOCUMENT_STORAGE.md`, `CONVERT.md`; the WASM `Card.body` / `overwrite` / `applyChange` / `positionAt` API). The preview↔editor half of the caret bridge lives in [PREVIEW.md](PREVIEW.md).

## The two models

The `Content` model is one flat `text` over Unicode scalar values (`\n` a line boundary, `U+FFFC` an island slot), a `lines` list (each a `kind` + a `containers` path + a `continues` flag) from which the block tree is *derived*, a set of freely-overlapping `marks`, and `islands`. It carries no node identity beyond island ids and `anchor` mark ids; a paragraph split or join is a one-character text edit.

ProseMirror is a nested node tree whose inline text carries a *set* of marks and whose positions count node boundaries; its identity is the tree itself.

Bridging the two is the codec's whole job: **flat-text-with-attributes ↔ nested-tree**. It is a translation layer, not a thin adapter: the content normalizes on every write, PM has no overlapping-mark or zero-width-mark concept, and neither side's positions are the other's.

## Direction: the content is truth; PM is its projection; edits are ops

Decode is a pure function content → PM. Encode does **not** rebuild a `Content` and `overwrite` it: it projects the new PM doc back to content (`pmToContent`, decode's inverse) and diffs `old → new` into a `ChangeBundle { delta?, islandOps?, lineOps?, markOps? }`, applied by `doc.applyChange(addr, bundle)`. Op-based, because:

- **anchors survive.** `overwrite` is value semantics: it drops the identity anchors (comment threads, stable references) of the previous value. `applyChange` splices, so anchors rebase through the edit.
- **it is the seam's grain.** The `delta` channel is CodeMirror-`ChangeSet` isomorphic; marks and line attributes are separate op channels by design. Lowering is a **whole-field diff, not a step replay**: rather than translate each `tr.step` out of PM's node coordinates and open-slice depths, it re-derives the content projection once and diffs `old → new` in one final USV coordinate space. The diff asks the store where its own rebase leaves the field's marks (`mapMarks`) and emits the difference, so it stays coverage-precise without carrying a copy of that rule.

Every edit lowers. `overwrite(addr, rt)` is left with two cases, neither a shape the vocabulary can't reach: a field not yet at *content rest* (an unset field, an authored string), which has no content object to splice and no anchors to lose, and an `applyChange` that throws. It costs that field's anchors, so it is the exception, not the path.

## Decode: content → PM

Fold the flat lines into the tree: group consecutive lines by common `containers` prefix (a shared `[ListItem]` path is one item's paragraphs; `[ListItem, Quote]` a quote nested in it), and join `continues` runs into one block (a code fence's lines → one `code_block`; a paragraph's hard breaks → one paragraph with `hard_break` nodes). The line `kind` selects the block node: `para` → paragraph, `heading{level}`, `code{lang}`, `rule` → horizontal_rule, `island` → a block island node, and anything else → a paragraph carrying the unknown kind (§Open sets).

**A continuation's metadata is its head's.** The fold takes `kind`, `containers` and `lang` off the line that opens a block and reads nothing off a continuation, which is the reading quillmark's own Markdown export and Typst lowering take of the same lines (`traverse::segment`). A continuation disagreeing with its head is therefore not a second reading of the block but a value nothing renders, and settling it is the store's rather than the fold's: the container half it refuses outright (`ContinuesAcrossContainers`), and the projection restates the head's kind on the next commit.

Contiguity plus an equal path is the whole of what makes one container, so `instance` is what tells one from an adjacent sibling of identical shape — two quotes in a row, two lists — which contiguity alone reads as one. The fold keys on it (a quote and an unknown alongside their name and payload; a list's run breaks where it changes) and the projection mints it, alternating against the sibling before it. Sibling adjacency is the whole scope: a container nested one level in already has a differing path above it. A run's `ordinal`s are gapless from 0, so a reset marks no boundary of its own.

Marks apply over their `[start, end)` range; PM splits inline nodes at mark boundaries, so free overlap of *different* formatting kinds is representable without loss (`strong[0,4)` + `emph[2,6)` → text nodes `{strong}`, `{strong,emph}`, `{emph}`). An island slot inside a `Para` line decodes to an inline node (an image); an `Island`-kind line decodes to a block node (a table), either carrying the island `id` and typed props.

Two mark kinds do **not** become PM marks: see §Marks.

## Encode: PM edit → `ChangeBundle`

`contentEdit(oldRt, newRt)` pairs the stored content with the new PM doc's projection (`pmToContent`) and diffs their text once; `lower(edit)` fills out the four channels around that splice, in `applyChange`'s application order (`delta`, then `islandOps`, then `lineOps`, then `markOps`, all in *final* coordinates: every earlier channel applied):

- **text**: a minimal single-splice diff of the flat USV text becomes `delta` ops (`retain` / `insert` / `delete`). A line split or join rides the delta: an inserted `\n` splits a line, a deleted `\n` joins; there is no separate split/join op.
- **islands**: an island's payload lives in its entry, never in the text, so `islandOps` is the only channel that reaches it. A changed `props` is `{ op: "set" }`, addressed by the id both sides carry; a slot the splice would have to type is `{ op: "insert", at }`, which places slot and entry in one op. A deleted island needs no op at all: the `delta` that removes its slot drops the entry.
- **line metadata**: when any line's `kind` / `containers` / `continues` changed, or the splice moved a line boundary, `lineOps` restate every line's metadata (`setKind`, `setContainers`, and `setContinues` for lines ≥ 1). Redundant restatements are safe no-ops, so the pass is correct whatever intermediate metadata the delta's split/join left. Equal metadata on both sides is only "nothing to do" where no `\n` was deleted or inserted: one splice that joins a boundary and opens another leaves the line count and the metadata array untouched while the store's inheritance slides the kinds along.
- **formatting**: the mark-coverage difference becomes `markOps` `add` / `remove` over final USV ranges, against `mapMarks(oldRt, bundle)` — where the store's own rebase leaves the field's marks once the text-moving channels have run. The rule it applies is the boundary's to state and this tier's to ask for, never to reproduce. Which marks union into one coverage set is the `(type, attrs)` pair the wire carries, the seam's own tie-break rather than a rule restated here, so a link and an unknown key the same way and neither has a case of its own (`markKey`).
- **anchors**: the decoration-set difference by id becomes `add {type:"anchor", attrs:{id}}` / `removeAnchor {id}`, positions already in final coords. The pre-edit side is read off that same `mapMarks` answer, so only the projection's set is passed in. An anchor is a point, and the plugin maps its held positions with the bias the store gives one, so the two agree on where an insertion at an anchor leaves it and the diff has no op to spend.

Everything reads against the *final* content, so the bundle reads the same way `applyChange` applies it. **A slot never rides the `delta`**: `applyChange` throws `IslandSlotInInsert` on an insert that carries one, so `lower` strips every slot inside the splice's inserted region and hands it to the island channel instead (`splitIslands`). That is what keeps island creation, and a splice that happens to span an existing slot, on the op path.

A **block** island is one bundle of three channels: the `delta` inserts the `\n` that opens the line, an island op places the slot, a `setKind` tags the line `island`. Stage order is what makes it expressible: `{ op: "split" }` could not open that line, since line ops run after island ops.

**The projection is total over the schema.** Every PM document the leaf's keymaps can reach projects to a valid `Content`, which is a statement about the keymaps as much as about `pmToContent`: a projection carrying more text segments than lines fails the content's `LineCountMismatch` invariant, and `lower` then under-specifies the bundle rather than refusing it — `applyChange` takes it, nothing reaches `onError`, and the field diverges from the leaf for the rest of the session. So a `\n` inside any textblock is the line boundary it is: `code_block` counts its own into `continues` lines, and so does every other textblock, where a `\n` arrives from a join that ran no `clearIncompatible` pass. `hard_break` is declared `linebreakReplacement`, so the passes that do run convert `\n` ⇄ break rather than flattening to a space, and a break is a `continues` line either way. The property is asserted as one (`tests/codec/roundtrip.test.ts`), over the chain the leaf runs — `decode → press → pmToContent → lower → applyChange` — rather than per fixed case.

**The leaf holds one spelling of each shape.** Totality settles what the store reads; the leaf is still free to hold a `\n` where `decode` puts a `hard_break`, which stores and previews as the line boundary it is while the leaf's own DOM collapses it to a space and the next re-hydrate swaps in the break under the caret. A range crossing a fence's edge is the gesture that opens one, since the fit that merges the two textblocks runs no `clearIncompatible` pass either. So the leaf's stack normalizes what its commands leave (`core/codec/breaks.ts`), over the document rather than at each command, which covers a paste and a drop alongside the keys. Shift-Enter, the one gesture that is *about* opening a break, binds in that same file and mints the canonical spelling directly — unmarked, `decode`'s own, with the caret's marks kept on the caret so a bold run reads across the break it wrapped at. The chain above asserts it as its fourth step: `decode(stored)` is the document the leaf is holding.

## Positions: USV ↔ PM

`usvToPM(pos)` / `pmToUsv(pmPos)`: a content USV offset is a character index into `text` (with `\n` and `U+FFFC` each one USV); a PM position counts node tokens. The map is a list of runs that tile the text: a `text` run where the two advance together, an `nl` run spanning a block boundary or hard break, an `atom` run for an island slot, each carrying its PM start and its USV start. The runs come off the same single walk that produces the content projection, so the map and the projection can never disagree; the whole list is rebuilt on structural change. Document order makes both coordinates increasing across the list, so a conversion bisects rather than scans: what keeps the bulk callers (every held anchor, on every commit) off O(anchors × runs). This is the function a `positionAt` result (`ContentHit.pos`) and a `FieldRegion.span` pass through to reach a PM caret, and the one a caret signal to the preview runs in reverse.

**UTF-16 hazard.** JS strings (and the text offsets inside PM positions) are UTF-16; content offsets are USV (code points). An astral character is two UTF-16 units but one USV, so the map converts; skip it and a caret drifts one unit per emoji it passes. quillmark's `usv` helper does not cross to WASM: the codec owns the conversion.

## Marks: formatting vs identity

The content mark set is two algebra classes, and they route to two different PM mechanisms:

- **formatting** (`strong` / `emph` / `underline` / `strike` / `code` / `link`) is a property of a range. ↔ PM marks. A round-trip through PM yields the union ranges, which is what content normalization produces anyway, so formatting is stable.
- **identity** (`anchor{id}`: comment threads, stable references; zero-width capable, no glyph) is a handle, not a property. It has no home as a PM mark (a PM mark needs a text node and carries no zero-width span). ↔ **PM decorations** (or plugin-held positions) keyed by id, carried across edits by `tr.mapping` and lowered to `anchor` mark ops. This split is what dissolves the "Peritext overlap vs nested marks" tension: overlap only bites where identity and formatting coexist, and they never share a mechanism.
- **unknown** (`{type, attrs}`) is neither: it is one of the four open sets, and routes to its inert carrier (§Open sets).

**A code line's text carries no marks.** `code_block` declares `marks: ''` (`schema.ts`), so decode builds its text node bare and the projection hands `emitText` an empty set. A formatting mark over code text has no reader anywhere — the fence and the Typst `#raw` emit the segment verbatim — so one that reaches a field survives the read and is gone on the first `markOps` diff; `importMarkdown` mints none and no gesture does. What reaches a code line is identity: an anchor is a decoration, and a comment thread on a fence holds.

**A `link` renders through a scheme allowlist.** An `href` is an attribute value rather than markup, so the path that keeps a document's text from becoming tags never reaches it, and `renderContent` paints marks outside a `contenteditable` (the tips card, whose channel is the document's own `$ext.editor.tips`), where a click is a plain one. `toDOM` emits an `<a>` for a scheme the surface makes clickable and an inert span otherwise; the prompt refuses the same set on submit. The gate is the render's and not the model's: a refused href stays on the mark and round-trips, so opening a document never edits it.

## Islands

A table or figure is one `U+FFFC` slot plus one `Island {id, type, props, loss}`. Decode maps it to a PM leaf node (block or inline by the slot's line); encode writes the slot char and the entry with its `id` preserved (stable identity, like an anchor). The **whole entry rides the node**, `loss` included: `applyChange` stores the class an island op hands it and re-derives nothing, so an edit that did not carry the class back would promote a degraded table to lossless on its first cell edit.

Known types carry a typed props shape pinned upstream: `ContentIsland.props` is `TableProps` for `table` and `ImageProps` for `image`; an island of any other type passes opaque (§Open sets).

An island edit lowers through `islandOps` (§Encode), and the entry's **value semantics** draw one boundary. A minted island id is this tier's to produce: the positional `isl-{n}` sequence continued past the highest the field holds, never a UUID or a clock reading, because the id is part of the document's canonical bytes (quillmark `DOCUMENT_STORAGE.md` §Island-id determinism). It is minted against the PM projection in hand, since an id minted against a stale content could collide with one the same transaction places.

## The table island

A `table` island's props are a pipe table: one column count shared by `header`, every row and `aligns`, and cells holding text and marks and no block content. The editing surface is a NodeView over that shape (`codec/table-view.ts`, `codec/table.ts`), and most of its decisions are the model's rather than a preference.

**A pick lands in the caret's container.** The block insert replaces an empty textblock and otherwise opens a block after the caret's (`codec/slash.ts`), both positions the parent's, so a pick in a list item nests the island in that item and one in a quote inside the quote. Nothing degrades on the way out: an island line carries its `containers` path like any other (§Encode), `toMarkdown` indents the pipe table to the item's content column, and the reference quill typesets it. Lifting to the body is refused: it spends structure the author wrote, and a memo numbers its paragraphs, so a table under point 2 is point 2's. The exit paragraph is the end of the body's affordance rather than the end of the parent's — an island in a non-last item has the next item to type in, and a paragraph minted inside that item is the unnumbered continuation the reference quill typesets (`codec/lists.ts`). A table inside a table needs no refusal: a cell mounts no slash plugin.

**A cell is its own content unit, and it takes the inline mode.** `TableCell.marks` are USV offsets into that cell's own `text`, so a rich cell nests one content unit inside the one this doc opens on. What resolves it is the mode the codec already runs: `richtext(inline)` is one paragraph, container-free, island-free, which is a `TableCell` exactly. A cell mounts a nested `EditorView` on `inlineSchema`, and the marks, the input rules and the selection popover come with it. A nested view carries none of the field's plugins: no history (`Mod-z` routes to the leaf's, so one undo stack covers a cell keystroke and a row op alike), no anchor plugin, no ghost. Plaintext cells are unavailable: an imported table's marks have to round-trip, so one would still have to render and preserve them with no mark mechanism — the hard half of the problem with none of the payoff.

**An anchor in a cell is preserved, never minted.** It is not in the field plugin's coordinate space at all (the position map holds one `atom` run for the whole island), so nothing here can place one, and the popover withholds its `anchor` button while the caret is in a cell (`focusedView` is what tells it, VISUAL_EDITOR §Chrome). Preserving is not doing nothing: a cell edit is a splice like any other, so a held anchor rebases through the cell's own text delta by the rule `applyChange` uses on a field's.

**Enter is the next row, forced.** A `TableCell` has one `text` and no line concept, and `continues` is a line flag with no cell analogue: a newline in a cell has no representation, so this is not a preference to settle. Tab traverses in reading order and appends a row past the last cell, which is the whole growth affordance a small default shape leans on. It declines at both ends, and that is the island's keyboard exit: the key is unclaimed, so focus leaves the grid the way it entered. Backward that is the first cell; forward it is the last cell of an empty trailing row, where the growth rule reverses on the shape it produced — a row is on offer, and walking off the end of an unwritten one refuses it, the reading an empty item's Enter takes in a list. Growth that never declined leaves Tab no forward exit at all, every press past the last cell appending, so a writer tabbing through a document grows the table instead of reaching the block under it. Escape leaves the cell for the row through the caret and then for a node selection over the island: two links of that key's chain, the innermost of them, and the second is the whole of what selects the island.

**Click-to-NodeSelect belongs to an atom with no interior.** An image is one: there is nothing to enter, so a press on it is unambiguous and it keeps the click. A table is not: it has cells, and every point on it is nearer to some cell than to the intent "select the whole thing". So a pointer press resolves to a caret everywhere but on a band control, and the island is three bands with three owners. Inside the frame (cell padding, the borders between cells) is the table's: a press focuses the nearest cell, measured against the mounted hosts' rects rather than against the last cell focused, since one gesture with two outcomes depending on history is a surface that feels haunted. Outside it (the island's own padding, the space beside the grid) is the document's: a press means "write here, beside the table" and lands a gap cursor, or the neighbouring block's own edge where the document holds a text position there (`prosemirror-gapcursor`, which the block-schema plugin stack mounts). A grip is the third, and what it acts on is a line, never the node. Pulling a press into a cell from outside would be the same violation at smaller scale: a caret arriving where the pointer did not aim. The guard is a `mousedown` listener on the NodeView's `dom`, because that is where PM arms the selection its mouseup takes; `stopEvent` gates the whole subtree, so widening it to cover a press would take PM's keydown routing with it.

**A selection is the subject of the next command, never a thing armed for replacement.** With an island selected, Backspace and Delete delete it (one `Mod-z` restores the node and the selection) and `Mod-C` / `Mod-X` take the whole island; a printable key collapses past it and inserts there: a block island takes a new paragraph after it, an inline island the caret after the image in the same line. One rule, both node types, and one prop: PM routes a printable key over a non-`TextSelection` through `handleTextInput` before falling back to replacing the selection. Insert-past rather than ignore, because the bands above remove the accidental arrival: the way left to reach a selected island and type is Escape out of a cell and type, which means "get me out, let me write". A dead keystroke stalls that; a paragraph after honors it and destroys nothing. Paste keeps replacing, stated rather than inherited: a paste is deliberate, and it is the gesture that swaps one island for another.

**A delete against an island selects it too, which is the same rule from the other side.** A Backspace at the start of the block after one, or a Delete at the end of the block before one, draws the node selection rather than taking the island (`codec/atoms.ts`, the last link of those two chains). A block with nothing in it is the empty line's instead, its Delete taking the line and leaving the island standing and selected, which is this rule's own state: the island goes on the press after (VISUAL_EDITOR §Chrome). Upstream answers a neighbouring atom by deleting it outright, and the block that neighbours a fresh table is the exit paragraph the insert parks the caret in, so the keystroke that eats a just-built table sits one press from where the gesture ended, with nothing on screen first. The link declines wherever the neighbour can be entered — a paragraph, a heading, a quote, a list — so every join the base keymap gives is untouched, and it answers after the list links, a Backspace at an item's start being the item's question whatever sits above the list, and a Delete at an item's end the seam below's.

**A header toggle is unexpressible, and the header is still a row.** `header` is a separate field from `rows` and `header: []` is not a table, so a table without one cannot be reached — but that is a fact about how a table is stored, not a rank the chrome answers to. Every row op works the flat `[header, ...rows]` list and splits it back, so whichever row lands at index 0 is the header afterwards: the header carries a grip like any other row, deletes (the row under it takes index 0), and drags (the row that displaces it becomes the header). The one row the model keeps is the last, there being no table under it, and the last column is the mirror case. Neither is a guard the chrome consults: a selection covering every rank of both axes is the whole table, and the whole table has its own delete.

**The rectangle is an invariant with no error channel, so it is a constructor.** Props normalize on write, and the editor holds optimistic PM and re-hydrates only on an external change (§Reconciliation), so an op that emitted a ragged table (a row op touching `rows` but not `header`/`aligns`, a paste) would leave the store rectangularized and PM ragged, permanently and silently. Text gets away with normalization drift because it is mark union; a table's is structural. Every row and column op therefore goes through one rectangularizing constructor, and the suite asserts overwrite-then-read equals the projection for each of them.

**The chrome is a band and a selection, and the band occupies no layout.** Every control is absolutely positioned out of the grid, hanging into a band the scroller carries as padding: a column's grip lives in its own header cell and a row's in that row's first cell, so a grip lines up with the line it names by construction, being inside it. The header's first cell carries one of each, on perpendicular edges that meet at no point. The two add bars hang off the grid's frame instead, being about an axis rather than a line. Nothing measures and no rect crosses a state channel, so the band tracks wrap, zoom, a font-size change and a horizontal scroll for free, while the grid itself holds the box a paragraph would. Gutter cells buy that same alignment and charge the table's shape for it: an empty row and an empty column in the accessibility tree, so a 3x3 table reads as 4x4 with its headers at column 2. The reveal is the control's own: one comes up while the pointer is on that control, while a bar holds the focus, or while it is what a gesture is about — the selected line's grip, the lifted one. What a control answers is which line, and a pointer crossing a table says nothing about which line it is crossing, so a band that arrived whole would put every control the table has up to answer a question the pointer has picked out none of. No control's box meets another's, so one is drawn at a time and it is the one the pointer is on. What that costs is the band's own announcement: a writer looking for a way to add a row finds it by reaching an edge rather than by hovering the middle. The targets are there throughout, an invisible button being hit-tested like any other, so what the reveal decides is what the table looks like under a passing pointer rather than what it answers to.

**A grip is pointer chrome, and it is out of the tab order.** A grip follows the cell it hangs in, which puts it behind the cell traversal forward and past the exit backward, so no Tab arrives at one. Carrying it there anyway spends a stop per line of every table in the document on a control no key reaches. What sits in the tab order is what a keyboard can operate, which leaves the cells and the two add bars — growth being the one thing the line verbs below do not carry, and a row's reachable from inside a cell besides (Enter at the last row, Tab past the last cell). A grip takes no focus by any route either: the caret is the island's one focus host, so a grip press paints its line and carries the caret onto it rather than taking it.

**The line verbs bind in the cell, over the rectangle the caret is in.** A grip press is not what a line answers to — the held rectangle is, wherever it was drawn from — so a row swept cell by cell moves exactly as the row a grip named does, which is the extent rule below reaching every verb rather than Backspace alone. One focus host and one verb set: the caret never leaves the cell, and with no rectangle held every one of these keys declines and is the caret's own, which is what lets them sit on keys a cell is already typing under. What the state says is the wash and the pressed grip, which is the accessibility tree too and not a second channel; nothing announces the draw, no live region shipping here.

- **Escape climbs a rung a press**: the row through the caret, then the island, then the shell's. The first rung is the entry the band had no route to, and it is the row rather than the column because the column is one arrow further on. Escape is what a writer already presses to get out of something, so the rung is found by the gesture that was going to be made anyway — where a chord is a thing to be told. What it costs is a second press to reach the island, and each press draws its own subject.
- **An arrow names the line on its own axis through the caret.** The line already held steps to its neighbour and carries the caret; any other rectangle turns into it, which is how a row becomes the column the caret is in and how a swept block resolves to a line. The caret stays inside the rectangle throughout, so the next arrow reads the line the writer is looking at. Alt+arrow moves the line instead, and over a rectangle that is not one it does nothing but keep the key: while a rectangle is held every arrow is its own, and an Alt+arrow handed back is the browser's Back on two platforms, mid-gesture.
- **Backspace reads the extent**, unchanged: it is the one line verb a cell already answered. **Enter hands the caret back**, the caret never having left. **A cell edit retires the rectangle**: a wash left up over text being typed says the next Backspace takes a rank, and it does not.

No chord appears anywhere in it, and finding one is what the alternative would have had to do. A cell is always in text-edit mode, so the spreadsheet pair is unavailable (Shift+Space types a space, Ctrl+Space is an IME toggle) and every single-modifier arrow is some platform's caret movement or the browser's own Back. Only entry has to be free of all that: a held rectangle outranks the caret, so every key the caret was holding is free while one is held.

**The chrome raises nothing, and every gesture is on a bar.** A grip press selects its line and a grip drag moves it, told apart by a dead zone; an add bar appends along its axis. That is the whole control surface, and it is what the band draws: a grip along each line's leading edge, and an add bar along each axis's trailing edge spanning it. A bar rather than a button at the end of the band, because what an add appends to is the axis and not a line — there is no line out past the last one to sit against, and the whole edge is the easiest target on the island to hit. It draws no glyph: a bar the length of the edge, arriving under the pointer one line past the axis, is the claim, and the accessible name carries the verb for everything that does not read position. The grip's marks are the island's only glyph, and they say draggable rather than which control this is. Insertion in the middle has no control: a row opens where the caret is (Enter at the last row, Tab past the last cell) or at the end and moves, which is two gestures the surface already carries instead of a third it would have to raise a menu for. A column takes the same pair — the add bar, then a move — from either device, a move being a keyboard gesture now and not the pointer's alone. Alignment round-trips in the content and no gesture reaches it.

**One selection, a rectangle of cells, and the verb over it reads its extent.** A grip names the rectangle covering its line; a press that travels out of the cell it started in sweeps the block it crossed. They are one state, because what Backspace means is decided by the rectangle and not by which gesture drew it: a rectangle spanning every row covers whole columns and deletes them, one spanning every column covers whole rows and deletes those, one spanning both is the whole table and deletes the island, and anything else covers no rank at all and is cleared. A row swept cell by cell therefore deletes exactly as the row its grip named does.

The both-axes arm is the rule's limit rather than an exception to it. What a delete over a selection means is that the selected thing goes, and every rank going at once leaves no table for a rank deletion to have produced. It is also the only route a pointer has to deleting a table, every press inside the frame resolving to a caret and every grip acting on a line. On a one-column or one-row table a single grip draws that rectangle, and its Backspace deletes the island: the column is every column and runs every row, so it is the table. What the arm costs is the whole-table clear — emptying every cell while keeping the shape takes two clears over sub-rectangles. That is the trade the extent rule is worth: deleting a table has no other gesture, and clearing one has two.

**A cell is never removed on its own.** Every selected cell goes one of two ways: out with its whole rank, or emptied where it stands. That is the model's shape rather than a policy over it — a rectangle with a hole in it is not a table. Nothing falls back: a rank the selection covers is a rank that goes, the header included, and what reaches the clear is a proper sub-rectangle, which changes no shape. So the clear is what a selection spanning neither axis means.

Deleting the table is reachable twice, and they are the same delete: the island selection, which Escape climbs to out of a cell or a held rectangle, and the cell selection covering every rank, which never leaves the grid. Both dispatch an ordinary transaction on the leaf's own view, so either rides the one undo stack and comes back in one `Mod-z`.

**The rectangle does not cross the clipboard** (§"Markdown at the edges"). No copy writes it and no paste reads it: a table reaches a field by import, and a `Mod-C` over a held rectangle is nobody's to claim.

The codec reports nothing to the shell: the leaf passes no island channel, because a cell index inside one island is not a coordinate its surface speaks, and nothing here floats, so there is no surface for the shell to place.

**A cell edit is one `islandOps` `set`.** The NodeView writes a whole new `props` onto the node with `setNodeMarkup` and the leaf's own commit path lowers it (§Encode), so a keystroke in a cell costs one island op rather than the whole-field value write `overwrite` would, and every identity anchor in the field survives it. Alignment is reachable by the same route, for the first time: it round-trips today and nothing in the editor could reach it. A reseed is decided per cell by comparing the stored value against what the nested view already projects, so the cell that produced an edit keeps its caret while an undo or a re-hydrate takes the fresh state. That state carries the caret's offset in, clamped — the rule a field's own re-hydrate takes — since a state built from scratch resolves to the cell's start, where the edit an undo reverses never was. A changed rectangle rebuilds the views instead, and the op that changed it says where the caret lands. An undo names none, being the outer history's transaction rather than an op of this view's, so the rebuild reads the seat the focus held — the caret's cell, by position, the island having no other — and restores it clamped into the rectangle that is there now. Without it the DOM under the focus goes with the rebuild, focus falls to the document body, and the next undo reaches no view at all.

**A landing in a cell is flagged for scroll, and on the leaf's own clearance.** Every route into a cell lands through one call — Tab and Shift-Tab, Enter into the next row or the one it appends, the arrow walk, and the reseat after a rebuild — and PM focuses with `preventScroll`, so an unflagged one leaves the caret typing where the pane has not moved to: past the right edge of the horizontal scroller a wide table lives in, or in an appended row below the fold. The rung is the leaf's line box rather than PM's 5px default, for the reason the leaf takes it (VISUAL_EDITOR §"Focus and the preview bridge"): a cell is one of the leaf's lines, and a caret revealed flush against the edge is the caret visible and unusable.

Every other island type keeps the literal placeholder the node's `toDOM` draws: the NodeView narrows through the boundary's own `isTableIsland` guard, and an unknown island renders as its tag rather than as a table it is not.

## Open sets: an unknown must survive an edit

Four of the content's discriminants are **open**: a mark `type`, an island `type`, a line `kind`, and a container name. Every member spells its payload in one `attrs` bag, known or not, so an unrecognized value is a construct some newer quillmark writes rather than a corruption: it loads carrying its own tag and the same bag a known one would, opaque here. Promoting a name to a built-in therefore moves no bytes, and a foreign bag beside a built-in is legal and drops unread.

Reading one is the easy half. A bare `line.kind === 'heading'` does not narrow (the residual `{ kind: string; attrs }` arm keeps a `string` live), so the checked path is the boundary's guards (`isHeadingLine` / `isCodeLine` / `isListItemContainer` / `isLinkMark` / `isAnchorMark` / `isTableIsland` / `isImageIsland`) read off `@quillmark/wasm`, never re-derived here. What a guard buys is the bag's shape — `attrs.level`, `attrs.lang`, `attrs.url`, `attrs.id`, a `list_item`'s three — never a sibling of the tag.

Writing is the half that bites. Lowering restates **every** line's metadata as soon as any of it changed (§Encode), so an unknown the PM tree cannot hold is destroyed by the first keystroke anywhere in the field: a document that opens intact and saves mangled. So each open set has an inert carrier that renders as its nearest safe neighbor and re-emits verbatim:

| Open set | Renders as | Carrier |
| --- | --- | --- |
| mark `type` | nothing | the `unknown` mark (`{type, attrs}`), non-exclusive so distinct families share a range |
| line `kind` | a paragraph | the paragraph's `unknown` attribute (`{kind, attrs}`) |
| container | its children, at the enclosing level | the `unknown_container` node |
| island `type` | the island leaf | `islandType` + opaque `props` on the node |

A carrier is dropped only by an **explicit** conversion (retyping the paragraph to a heading, lifting out of the container), which is the one place losing it is what the user asked for. A copy is not one of them: each carrier's tag and payload cross the DOM the clipboard runs through (§Markdown at the edges).

## Inline mode

`richtext(inline)` and `plaintext` fields are single-paragraph, container-free, island-free. The codec runs a constrained PM schema (one textblock, no block splitting, Enter suppressed); `plaintext` runs that schema **declaring no mark types at all**. Same decode / lower / position machinery, narrower schema.

**A plaintext field's mark-freedom is the schema's, not a rule per path.** The boundary refuses to coerce a marked content back to `plaintext`, and the refusal lands at render, where no commit-time gate catches it — so a mark has to be unreachable rather than rejected. Declaring none is what makes it so: a format command finds no type to apply and the surface offering it withholds itself (VISUAL_EDITOR §Chrome), the shorthand rules build nothing, a paste parses its marks away, and a browser's own `Mod-b` binds nothing. Anchors go with them: an identity anchor is a mark on the wire whatever it is in PM. Decode drops any mark a content arrives carrying, so a value an older build marked opens as its text and heals on the next commit rather than throwing on the read.

**A plaintext field's codec is the boundary's, reached through `reader.getContent`.** Its rest form is the literal string, and its content is that string verbatim: the leaf never parses it, and `importMarkdown` on it would consume the delimiters the author is entitled to. The write side stays the content-object round-trip via `overwrite` / `applyChange`, which the mark-free inline schema keeps conforming. The reference quill declares both types (`subtitle` plaintext, `epigraph` inline richtext) but no two fields differing in nothing else, so the mode's suite builds a two-field schema of its own, the only one in the package that does: the declared type is the whole variable.

The schema distinction is also what sizes the leaf: a constrained leaf holds one paragraph, so it is one line tall and draws the same recipe a scalar control does, while the full schema grows. **The codec owns the stylesheet both depend on**: `codec/prose.css`, imported beside ProseMirror's own, which carries no block reset and so leaves every block on UA defaults. It lives here rather than per component because every prose leaf in the package (field, body, array element) mounts through the codec and inherits it without restating it. What the sheet states is that a span is code and a line is a heading; it predicts nothing about the size the rendered paper sets them at, which the package cannot know for a quill it has not seen.

## Markdown at the edges

Markdown never represents an edit, and the clipboard is not how it reaches a field. One of the three doors is open:

- **whole-document serialize**: `Document.toMarkdown()`, read-only, canonical.
- **paste**: shut to markdown, and to every construct this package's own `data-*` names do not spell. What a paste gets is ProseMirror's own DOM parse against the schema above: lists, headings and marks survive it, markdown text arrives literally, and a `<table>` flattens to its cells' text, nothing on the web naming an island. A field takes markdown by import — Quillmark's conversion to a DTO, or the source editor — which is a whole document with its anchors rather than a fragment that has to be rebased onto one. One rule reaches past the shut door on purpose: a `<pre>` stating a language, by `data-lang` or the `language-*` class every highlighter emits, arrives carrying it, and that is the whole of how a `code_block.lang` is minted in the visual editor (VISUAL_EDITOR §"Settled and open").
- **copy**: the clipboard takes PM's own serialization. Nothing writes markdown, so there is no lossy export to warn about.
- **the pair is a tier, not a rendering.** A copy and a paste inside one body run the whole document out through `toDOM` and back through `parseDOM`, so an attribute written there and not read back is a value an ordinary copy destroys — §"Open sets"' three carriers included, whose whole job is surviving everything but an explicit conversion. Every attribute the schema writes is read back: a fence's language, a list's `start`, each carrier's tag and its JSON `attrs`, an island's `props` and `loss` beside its type. The one value a paste does not carry verbatim is an island id, which is an identity rather than a payload: an id the field already holds is re-minted on the way in (`codec/islands.ts`), so a copy lands beside its original instead of as a second island wearing one id, and a cut pasted back keeps what it had.

## Reconciliation

The content normalizes on write (marks sorted and same-kind-unioned, zero-width formatting dropped, invariants enforced), so `decode ∘ lower` is idempotent only *up to normalization*: a projected PM doc and the re-decoded stored content agree after normalize, not byte-for-byte. The editor holds its optimistic PM state and re-hydrates a field only on an **external** content change (another edit source, a paste, a `revise`), gated by canonical-content equality scoped to the field that changed. Caret continuity across a leaf's *own* edits is not this gate at all: it is PM's `StepMap`, inside the leaf the codec mounts, which is why an own-edit never re-hydrates and never moves a caret.

## Seams

- **anchors are decorations, not a document mark.** Plugin-held positions keyed by id, mapped through `tr.mapping` and lowered to `anchor` ops: the split that keeps identity off PM's mark mechanism. A selection mints one through the field seam `insertAnchor(id, pos)` / `removeAnchor(id)`: a zero-width edit carried on an `anchorKey` meta that folds into the plugin set and commits through the same mark diff a formatting toggle does. The id is caller-supplied, unique and invariant per the boundary's anchor-id policy ([DOCUMENT_MODEL.md](DOCUMENT_MODEL.md)); a duplicate is a no-op. A move into the document proper, and the comment-thread UX that gives an anchor visible chrome, are post-V1.
- **island props are typed at the boundary**, so the codec reads the shape off it; no local `IslandTable*` / `IslandImage*` duplicates or shape guards (DOCUMENT_MODEL §Stability seams). The union and the narrowing rule are §Islands above; the island channel's producer is the table NodeView (§"The table island").
- **island edits are ops, not an overwrite.** The `islandOps` channel reaches an island's payload and places a new slot, so a table edit keeps every identity anchor in the field. `lower` diffs the island sets and emits it; the overwrite fallback has no island case.
- **overwrite fallback** is a field not yet at content rest (nothing to splice, nothing to lose) and any `applyChange` that throws. Both are `overwrite(addr, rt)`, paying that field's anchors: the exception, not the path. The throw path drops the field's held anchors where the ops path would have kept them; whether it earns a repair pass of its own is open.
- **input rules and the PM schema** ship: the markdown shorthands are PM input rules producing ordinary transactions this codec lowers; markdown is an input shorthand, never the stored form. Each block rule is one regexp over a command in `codec/blocks.ts`, which is what a slash pick runs too, so a construct's two doors are one implementation. No table-entry rule ships: a pipe row is not a prefix a rule can fire on, so island insertion is the slash menu's alone (`codec/slash.ts`), which is where a minted island id comes from.

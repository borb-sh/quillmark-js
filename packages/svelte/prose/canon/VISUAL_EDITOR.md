# Visual Editor

> **Implementation**: `src/lib/visual/`

## TL;DR

The headline WYSIWYG surface over a Quillmark document: the card/field structure, the schema-driven fields, and prose-body editing, and how they compose into one editable tree. This doc owns the **composition**; the per-field content↔ProseMirror translation is [CODEC.md](CODEC.md), the rendered view and its caret bridge are [PREVIEW.md](PREVIEW.md), the live `Document` and WASM boundary are [DOCUMENT_MODEL.md](DOCUMENT_MODEL.md). Grounds on quillmark's document and schema model (canon: quillmark `CARDS.md`, `SCHEMAS.md`, `DOCUMENT_STORAGE.md`) and the WASM edit surface (`Document`, `quill.writer(doc)`, the addressed content verbs).

## Federated, not monolithic

The VisualEditor is a **thin composition layer** over many small editors, not one ProseMirror document spanning the page. The schema is the outline, a Svelte tree renders it, and each content leaf (a body, a `richtext` or `text` field) is a separate sub-document with its own PM state, view, history, and plugins; scalar fields are plain form controls.

The content already stores a document as separate leaves at distinct addresses of distinct types: a card's body, its `intro` richtext field, its `signature_block` array are three `Addr`s carrying three value types. A single PM document would re-encode that schema tree as PM nodes and re-derive every address from tree position, paying a markdown serializer into library internals, a parser that patches token handlers, and a plain-text fallback that destroys structure on the next round-trip. Federation deletes that layer. The editor renders the schema directly and lets each leaf pick its editor by type; it owns structure, control selection, card operations, focus, command dispatch, and diagnostics routing, and delegates the substance (content↔PM to the [codec](CODEC.md), geometry to the [preview](PREVIEW.md), truth and mutators to the [document model](DOCUMENT_MODEL.md)).

## Structure mirrors the schema

The layout is a direct projection of `quill.schema` (`QuillSchema { main, card_kinds? }`, each a `CardSchema { fields, ui?, body? }`) joined against the live `Document`'s payload. The editor performs that schema × payload join itself: there is no Quillmark projection for the editing surface (canon: `SCHEMAS.md`, the editor row of the projection table).

**A card is a list of fields**, rendered in **declaration order** (the `fields` map key order; order is not a `ui` hint), then a body. The body is the field-less content leaf (`Addr {card?}`, no `field`), gated by `body.enabled`. Metadata and body are **one abstraction**: a body is a richtext leaf, a `richtext` field is a richtext leaf, and both take the same prose-field editor and codec, differing only in address form (`{card}` vs `{card, field}`) and prominence. One field list, controls chosen by type: no metadata-vs-body dual mode.

**A control per field type** (canon: `SCHEMAS.md` field table). A content type — `richtext`, and the literal codec's `text` — mounts a prose leaf, its line shape and its codec narrowing the PM schema it runs ([CODEC.md](CODEC.md) §Inline mode); a scalar takes a form control. Either content type is one line unless it declares `multiline: true` (`oneLine`), and `literalText` reads the codec: a one-line `text` mounts one mark-free textblock, a `multiline: true` one the plain schema's paragraphs and breaks. No declared type takes the text input, which is the control a type this build does not know falls to. An optional cell (`t?`) takes its base type's control, the `?` moving the render floor and nothing else: every read of a type strips it (`baseType`). `array` is an add/remove repeater committing by value. A scalar or prose row is edited in place and holds no reorder: a mis-order in a list of strings is a retype. A paste of several lines into a prose row is a row per line, the first landing where the caret is and each after it a row below as Enter opens one, up to the array's `max:`, the last row taking what is left joined. An `object` row collapses to a summary — a box titled by its first short text cell (a one-line `text` or `richtext`, read as its text), else, while that cell is empty, by its indexed name — and opens onto the subform, whose vertical hangs at the row's edge under the summary that disclosed it, as a variant's cells hang at the discriminant's edge and a matrix's columns at the tick's: every vertical hangs at the edge of the control it unfolds from, so one step in is one nesting distance wherever it is read, and what a control unfolds stands one rung below it. Each row opens and closes on its own, a press on its summary toggling it and nothing else, so a landing that opens one row never folds the row the author was in; collapsed, an array of ten records is ten lines and one figure. An `object` row carries a drag handle hung off its head's start edge, a table grip's twin, at nothing until the pointer is on the row. The drop is the row under the pointer, drawn as the table island's rule. A drag held at its scrollport's edge scrolls toward the rows out of view, and the drop follows the scroll. The handle is pointer-only and out of the accessibility tree, since a press on it does nothing. Its keyboard twin is Alt+↑/↓ from anywhere in the row, which the row's summary declares. The keys answer from the nearest row, so a press inside a nested row never moves the record around it and inside a nested table or list of strings moves nothing: a record of four cells is not a retype, and a move is one splice of the ids and the values together, so the row keeps its session id and everything mounted under it. A row's controls are slabs over the end of its own box; a table's row carries the remove alone, pinned to the end edge of the box the table scrolls in. An array declaring `max:` disables its add chip at the cap and draws the count beside it (`2 / 3`): a disabled button takes no focus, so the count is the carrier of the promise disabled makes (§"Enum policy"); nothing draws for a document already past the cap, `validation::cardinality` being a warning. A `text` or `richtext` field declaring `max:` holds its leaf to that many characters, counted as Quillmark counts them (`capCount`, `cap.ts`), at every depth a prose leaf mounts: a keystroke at the cap lands nothing, a paste lands what fits, and a value stored past the cap edits down and grows no further, so `validation::over_length` is a warning no gesture here earns. A labelled leaf draws its count at the end of its label row (`12 / 40`), the count describing the leaf, since a refused keystroke changes nothing else a reader perceives. An element's control is its `items` type's: a content-typed element mounts a prose leaf, one textblock whatever it declares since Enter is the repeater's, reading through `reader.getContentAt(addr, [k])`, which decodes an element at the codec its declared type names. So what an element rests as — the content object, a `text` literal, the authored string a transport door left — is the boundary's business rather than the row's, and a `text` element carries its own asterisks under the mark-free schema exactly as the field does. The write is the other lane and unmoved: an element has no op address, so the row hands its re-encoded `Content` up and the array commits whole, the typed writer resting it back at the element's own form. A bare value under an `array`, which the render reads as the one-element list it spells (canon `SCHEMAS.md` §"Type coercion"), draws as that one row, reading the literal at the element's codec since the boundary answers no element of it, and the first gesture writes the list whole. `object` is a nested subform over `properties`: a scalar draws its own control and a content property mounts the same by-value prose leaf an element does, reading through `reader.getContentAt(addr, ["motto"])` — the boundary walks `items`, `properties`, a variant's key and a matrix's member alike, so a cell reads at its own codec whatever depth it sits at, and a subform under an open `object` row reads at `[k, "motto"]`. A `richtext` or `text` property declaring `multiline: true` takes the whole row, on the block schema or the plain one, a track beside it standing in whitespace once it holds paragraphs. A prose leaf is held over content it cannot edit: narrowed to one textblock, over anything but one plain paragraph; on the plain schema, over anything upstream's `isPlain` refuses once its marks are set aside, a mark being what decode drops and the next commit heals; by value on the block schema, over an island. The decode joins lines and drops containers and islands, and the first keystroke would write that loss back; a by-value leaf mounts no island view, so an island in it draws as its placeholder tag, an atom a keystroke deletes unseen and nothing edits. A held leaf draws its content on the block schema, read-only, with a note in its box, and commits nothing. Whether it holds is read off the value it mounts, by upstream's rules `isInline` and `isPlain` and by the content's own `islands` (`fitsLeaf`), rather than off a diagnostic: a set routed to a field can predate the value it arrives with, and upstream reports a one-line `text` value that is not plain as `validation::not_plain` alone. A field judges it at mount and on every re-hydrate (`createField`'s `applyExternal`), which each set routed to it asks for (§Diagnostics), so the re-validation after an external write releases the hold or takes it; a by-value leaf, an element or a cell, judges it at mount and on every replacement of its view, which its parent's re-derive asks for wherever the content it hands down differs from what the leaf last committed or took (§"Edits are ops to the live Document"). A trailing empty line holds no narrowed leaf, the decode joining it at the cost of a space: it is the newline a YAML `|` scalar keeps in a `text` value, which upstream ignores. An `enum` declaring `variants:` is the discriminant's select over that same subform, drawing the cells its world brings into play (§"Enum variants"). A `matrix` is grouped ticks over its roster, columns unfolding under a held member (§"The matrix"). The text-ish types are the model's plain-vs-formatted pair, `text` and `richtext`, both prose leaves that reach the codec; `enum` is a form control.

**Controls compose by nesting, and depth is bounded by what is open, not by the schema.** A nested `array`, `object` or `matrix` property mounts its own control at the next rung of the same figure — a subform's vertical one `--_qm-nest` further in — rather than a line pointing at the source view. A repeater inside an open row is collapsed rows again, so an open tour under an open vector is one figure at two rungs, whatever the schema's depth. A nested container takes its subform's full span at every depth (`packable`, one rung in). Commit stays by value all the way up: a row has no op address, so an edit inside a nested row re-encodes the field whole through `writer.set`, exactly as an element does — at depth that is the whole subtree per keystroke in a nested prose cell, the bound the design accepts rather than one it fixes. Provenance stays coarse at depth (a nested cell takes its static `sub.default`; `resolve` carries one rung per field), obligation stays per leaf, and undo stays per leaf: removing a nested row takes its subtree with it.

**Two controls compose by position and recurse into nothing.** An `array` of `object` asking `ui.layout: table` on its own `ui` draws as a table where every cell of the row is short: an `enum`, a number, a boolean, a date, a one-line prose leaf. A column is a property, identified by where it sits under a header, and each cell is the property's ordinary control with no label of its own, its accessible name the row's and the column's composed. It is the record list's row machine in another presentation — the same ids, splices and landing over rows that are always open — not a second tree, which is what keeps one landing lane. Enter and Backspace ride the cell's own control, so they answer from a prose column, the one that leaves those keys free where a select opens its list, a switch toggles and a date segment edits. A table's row holds no reorder: every cell of it is on the line, so a mis-order is a retype as it is in a list of strings, where a collapsed record's cells are folded away. Its remove is the row's last track, pinned to the end edge of the box the table scrolls in, so the one gesture the row keeps never needs a scroll and costs the clip one tap floor. That every column is a leaf is the loader's contract, a container column being `quill::table_column_not_leaf` at load; the request to draw a grid is the schema's and the answer is the surface's: a row holding a block prose cell declines it at load width and every width after, since the fallback cannot be a container query (a query cannot choose which components mount) and a row that would stack inside a cell is not a line. Every row of it open, the table stands where an open row's subform stands, a rung inside the field behind the subform's vertical: a header set on the field's own edge at the label's register reads as a row of compact fields, and the stroke is what says the columns are the field's insides. A column floors at the width a control that fills its track stays usable at, and one drawing a switch floors at nothing: a mark is one width at every width, so a boolean's column is as narrow as its own name, where a section's grid and a subform's stand a boolean in a track its neighbours share. Narrower than its columns the table scrolls sideways inside its own box, the stroke, the inset and the remove holding still; nothing measures and nothing remounts. The matrix is the other (§"The matrix").

`ui` hints drive layout, not structure: `ui.compact` asks a field to share a row and is granted only where a neighbour packs with it, `ui.layout: table` asks an array for its grid. `ui.layout: flat` is deprecated upstream and drawn nowhere. Undeclared, `ui.compact` is read off the type: a date, an enum, a number or a boolean asks, and text does not, its type saying nothing of whether a value is a rank or a subject line. A field's top-level `title` labels it. A card's header is its `$ext.editor.title` rename, else its kind's `title`, else its own first short text cell, else the humanized kind (`cardTitle`; canon: `CARDS.md`): a kind that declares `title` names every instance with it, and one that declares none names each from its own values, the rule a collapsed row's summary follows. That header follows its field as it is typed: a one-line prose field's lane re-derives nothing, so the header recomputes on the leaf's own commit and holds beside the model until the next bump. A kind named before any instance of it exists — in the add menu, in the retype select a card of an undeclared kind offers — reads its `title`, else the humanized kind.

**Layout is CSS's, not JavaScript's.** A section is one grid: `placeFields` (`structure.ts`) gives each field a span and nothing else, a container query steps the column capacity, and fields auto-place into it. There are two spans and no third: a field packs into one column, or takes the whole row. A compact field stranded — nothing packed beside it — takes the row, a lone narrow track reading as truncated against the width it leaves empty, and a shared row being the whole of what the hint asked for. Nothing measures, so there is no observer to loop, no first pass at the wrong capacity, and no resize that remounts a prose leaf. A field spanning a shared row subgrids onto the section's own tracks, so controls in one row start at one baseline whatever a neighbour's label did. A full-span field's subform draws its own vertical and steps its properties one nesting rung in from it, and it is a query container over its own width: its tracks step at the widths a section's do — one recipe, `.qm-tracks` in `controls.css`, so the ladder is minted once — over the width the properties actually get, and a subform three rungs in draws the count its box carries rather than the section's over a box three `--_qm-nest` and three verticals narrower. What a property shares with the field above it is the rhythm, not the edge. A card-level object's properties, and those of an object nested in it, are placed as a section's fields are, by `placeFields`, so a field moved into a group keeps its row; a record's cells (an array's row, a variant's world, a matrix member's columns) pack wherever they are short, being one record's values rather than a card's fields. **A headed subform stands at the depth of what holds it.** An object a panel's header names (`GroupSection.head`) — a card's top-level `object`, and one alone in its legacy group, read off the group holding one `object` and no other field — draws no vertical and no rung, and the grid's rows keep the rhythm of the panel around it, inherited rather than restated; its tracks are still its own count over its own width, which is the panel's width, so they step as the panel's do. The panel is its frame, so the header names it, taking the field's label id for the subform's `aria-labelledby` and parking its description beside a hint of its own, and the field draws no label to say the panel's name twice.

**A card's top-level `object` is a panel.** Depth is what makes it one, not a type (canon: Quillmark `SCHEMAS.md` §Grouping): on a card, `main` or a kind, each `object` joining no `ui.group` draws as a panel of its own, its `title` the header and its `description` the hint beside it, its properties standing flat inside, since the panel is the frame a subform would draw (`objectSections`). Everything else stands unframed above the panels, and the panels follow in declaration order; the loader warns `quill::field_after_object` where a field declared after a panel would draw above it, so the order declared is the order drawn. An object inside an object is the nested subform it is anywhere, so there is never a panel inside a panel; an `array` of `object` stays its record list or table. Panels are an accordion, one open at a time and the first open on mount, and a closed one is `inert` rather than merely clipped ([ARCHITECTURE.md](ARCHITECTURE.md) §Styling): a header announcing `aria-expanded="false"` over reachable focus stops states what its content contradicts. A card declaring the legacy `ui.groups` registry draws each `ui.group` as a panel too, after the object panels and in registry order (`groupSections`, joined by `cardSections`), its objects subforms inside; an object alone in its group is headed by the group as a panel's object is. That path goes with the Quillmark MAJOR that drops `ui.group`.

**A press on a section header keeps that header in the fold.** One open at a time means a press can be carried off the fold by exactly one box — the panel closing above it, since a panel opens under its own header — and the answer is the trip every landing here takes: the minimum, to the nearest edge, never a centring (§"Focus and the preview bridge"). A header the collapse never carries out of view costs no scroll at all; one it would rides up and parks at the edge, which is where a section just opened wants its header, the fold below it being the room its fields unfold into. Holding the header on the line it was pressed on is the stricter rule and the worse one: it pins a press near the foot of the fold there, and opens a section into the screen it is sitting on the edge of. The trip is taken per frame over the motion rung, so both panels keep their animation (`visual/hold.ts`). Scroll anchoring answers none of it: the platform picks its anchor off the layout, and what fills the viewport as a section collapses is that section's own content, whose top never moves.

## The commitment ladder

**The editor projects the commitment ladder.** Per field: show the authored value; else the `default:` where it prints, held as the control's value and never written back unasked (it lives in the schema); else words about the value. **No field is required**, so the surface marks none: whether a field wants an answer is its `description:`'s to say, and a `default:`'s presence or absence says only what an unanswered field prints. Warnings do not draw (§Diagnostics), and completeness stays a read the host makes. A field's `description:` rides its label as a tooltip.

**A default that prints is the value, and an edit takes it.** An unset field holds its resolved `default:` as the control's own value — a text or number input's text, a prose leaf's content, an array's rows, an enum's trigger, a date's digits, a checked switch's track, a matrix's ticks — at the default rung (`--_qm-ink-default`, a mark's fill `--_qm-accent-default`, `theme.css`): near enough to `ink` to read as the answer the render prints, a step off it so it never reads as written. Nothing is written until an edit, which writes the whole value as authored with the edit in it, so tabbing through a card writes nothing and freezes nothing against the next quill version. A keystroke typed and removed pins a default on purpose, and a free-text field whose default prints has no gesture back to it once taken, emptying it being the empty answer (below); the enum keeps its sentinel (§"Enum policy"). What a take writes is what the author declared: an array's literal rows, not resolve's, which completes a record against `items`. A text input takes at its first keystroke; a prose leaf at its first transaction that changes its document or an anchor, `createField`'s `fallback` marking the editable `data-default` until then; an array at any gesture, every one of which commits the whole array; a number at the `change` that settles an edit. A date seats the default as the primitive's value on entry from outside the field, so a segment edit commits a whole date with the other segments the default's, and unseats it on leaving without an edit; the primitive re-reports its own value as a segment loses focus, which the field reads as no edit. A segment edit that empties a segment holds the field empty while the focus stays inside it, painting no default. The edit that empties the last segment writes the blank at once (§"Emptying a control writes what empty means for its field"), and leaving with a segment still filled puts the stored date back. It does not hold the default as its value at rest, which would read as filled to every path that reads the primitive; at rest the digits are painted into the segment text over an unset primitive instead. A nested cell takes its static `sub.default` the same way (§"Structure mirrors the schema"). A date holding `today`, written or as the default, prints the render date and wrote none of its digits, so they take the default rung; its Today toggle is pressed, at the default rung while the default supplies it. The toggle writes `today`, pressed writes the digits it showed, and a segment edit writes a whole date. Its state is its fill and its glyph, and the pointer draws none: a hover fill reads as pressed. Off, it rests hidden where a pointer can reveal it.

**Where nothing prints, a control draws words**, at the label rung: what it says is about a value rather than one. An optional cell (`t?`) unanswered prints `none`, which it ghosts at rest, worded `strings.optionalGhost` wherever a control draws a text ghost (a number input, an enum's trigger, a prose leaf); a blank or absent enum `default:` draws `ui.blank_title` (§"Enum policy"); a date with no default draws the primitive's `mm`/`dd`/`yyyy`. An unset `text` or `richtext` whose `default:` prints nothing — none declared, or a blank one — draws nothing: the schema declares one value per slot, its `default:`, and a field's `title` and `description` are text, which the label and its parked description already carry. An answered cell ghosts nothing, an empty answer printing empty; an optional cell's prose leaf emptied is unanswered again (below), so its ghost comes back. The surface draws no schema-sourced guidance the blueprint does not carry; a `ui` key carries no facts, and a filled page is the quill's example document, a whole document a host opens rather than a ghost. Guidance is per-field **or** document-level, never a third thing hanging off a field: no field carries a tips surface of its own, and document-level hints ride the `$ext.editor.tips` card instead (§"Card operations"): a chrome channel, not a schema key, so it makes no claim about any one field. Nothing gates: an incomplete document edits and renders fine (canon: `SCHEMAS.md` blank-fill render). Completeness is a read of `quill.validate(doc)`, not a gate.

**Emptying a control writes what empty means for its field.** Over a default that prints, a date and a prose leaf write the empty answer (`""`, the empty content), the one answer that prints empty there, and an array whose last row goes writes `[]`: a user who deletes a default's text never watches it come back. A prose leaf emptied writes that answer at every cell but an optional one. An optional cell (`t?`) declares no `default:` (`quill::optional_default`), and emptying its leaf is the way back to unanswered that upstream asks an editor to offer (canon `SCHEMAS.md`): the key goes, a field's through `doc.removeField(addr)`, the quill-free store lane, and an object's property's, a table cell's, a variant cell's or a matrix column's as the container committed without it, so the cell prints and ghosts `none` again. A text input's blank lowers to the same removal where unset already prints nothing. An array element is positional rather than a key, so an emptied one holds the empty answer. A number has no empty answer (canon `SCHEMAS.md`: no uniform "blank, not default" for a non-string type), so a blank number unsets and its input takes the default back. A date is a string type and has its blank, written as the last segment of a date cleared segment by segment empties; entering a stored blank seats no default. A text field commits a clear as it lands, an empty answer and an unset over nothing both rendering empty, so no clear flashes the field through its default. `EnumField` gives unset a ghost sentinel option: picking it unsets, picking any value (the default included) writes, so "commit the default" is expressible and shown-never-written stays visible. An explicit empty over a non-empty enum default is a member the quill declares (`undecided`, `n_a`), never the blank (canon `SCHEMAS.md`), so the rule above stops at free text. `BooleanField` is exempt (a switch has no blank), except where it is optional: an unset `boolean?` prints `none`, which neither face says, so its thumb stands at the centre and its role is `checkbox`, the toggle role with a `mixed` state, `switch` reading one as false. A press answers it; nothing returns it to unset. Every numeric commit settles at `change` (blur/Enter): a per-keystroke commit round-trips transient invalid prefixes (`-`, `1.`) through the boundary and flashes a coercion diagnostic the `role="status"` live region announces. A numeric entry is plain decimal, an optional sign and digits and for a `number` a `.` and an exponent, the form a value too small or large for digits reads back in: a keystroke that leaves the text outside a prefix of it does not land, a `number`'s `,` landing as its `.`, while a deletion, a paste, a drop and an IME composition land as they come. A settled entry in the grammar commits as a number and anything else reaches the boundary as the raw string, whose coercion judges it: `Number()` reads `0x1F` and `Infinity` as numbers, and `1.000` as a whole one.

## The address is the spine

Every editable unit is keyed by an address: a content leaf by `Addr {card?, field?}`, a scalar by its `{card?, field}` path, a card by position. One identifier is what `applyChange` targets, what the preview bridge speaks (`ContentHit.field`, `FieldRegion.field`), what a diagnostic routes to, and what Svelte keys the tree on.

But cards are **positional** in the content (`cards[i]`): index-keyed loops, stale-index write guards, reused-component reconciliation, phantom placeholders. So the VisualEditor keys each card *instance* by a **session key** and resolves that key to an index only at the mutation boundary (`moveCard`, `applyChange(addr)`). A reorder is a `moveCard` plus a key reorder; no leaf remounts, no PM instance is re-fed a swapped document, no caret is lost to a swap.

**The key leaves the editor.** No address survives a reorder — `Addr` and `DocPath` are both positional, so a host holding `cards.indorsement[2].from` names a different card after one `moveCard` and is told nothing — so every payload naming a card carries its `cardId` beside the address it already carries: `EditorChange`, and the active leaf. `'main'` is the main card's key, the same token the leaf-key space already spends. A removal carries the key with no address: the index is meaningless once the card is gone, and the key is the only handle left to drop. The tips dismissal carries neither; it is document-level chrome that rides `main`'s `$ext` and names no card.

The parallel array is not a workaround. With no card handle in the document, `cardIds` is not a cache of a document-side truth — it **is** the identity, and there is nothing to reconcile it against. So the editor **owns structural mutation for the session**: the keys track the inserts, moves and removals it performs, and a host that mutates the card array behind it re-seeds the surface rather than expecting the keys to follow. A `cardId` is session-scoped by construction: it does not survive a reload, and a host persisting one is persisting a session key.

### One vocabulary in the hooks

**Paths for places, indexes for structure ops.** Every hook naming a place speaks the canonical `DocPath`: `onCaretMove`'s `Place`, `EditorChange.path`, the active leaf's `field`. It is the grammar `Diagnostic.path`, `ContentHit.field`, `FieldRegion.field` and `session.regions()` already key on, so a host wires the editor to the preview as a pass-through and routes a diagnostic back with the string it was given. `Addr` stays the mutator currency — the document verbs take it, the card verbs take indexes — and `enumOptionAllowed` keeps its `Addr` because it runs per option per derive, where minting a path is a string mint on an address that has one for free.

`/core`'s `fieldPathForAddr` / `addrForFieldPath` are the hop between the two, public and beside the grammar they speak (`cardPath`, the card's own path, is the editor's). `addrForFieldPath` is also the one parse: the diagnostics router reads it rather than keeping a second copy of the walk.

A structure op's path names the card (`cards.<kind>[i]`), not the body leaf inside it: the change is the card. It is minted after the mutation, since an insert's card does not exist in the previous tree and a retype's kind is the previous kind.

**A bare path is never cheaper and sometimes wrong.** A hook carrying a `DocPath` and nothing else would spare a host the sites that parse an index back out, except that the struct carries the path too, so `parseDocPath` is one call under either shape. And it loses where the struct does not: an outline highlighting the active card reads `cardId` directly, where a bare path is parsed for an index that is wrong after the next reorder — the trap `cardId` exists to close.

## Edits are ops to the live Document

The VisualEditor holds the live `Document` (via `DocumentWriter = quill.writer(doc)`) and writes ops at an address: never a markdown string, never a whole-document re-serialize:

- **prose leaf** → the codec lowers each PM transaction to a `ChangeBundle` and calls `doc.applyChange(addr, bundle)` ([CODEC.md](CODEC.md)): the per-keystroke path; anchors rebase. The typed writer's markdown-import `setBody` is *not* it. A literal (`text`) leaf is the exception, committing its whole text through `writer.set` (CODEC §Inline mode).
- **scalar / array / object** → the typed writer: `writer.set(name, value)`, or `writer.card(i).set(...)`. Schema-checked; an undeclared name throws.
- **structure** → `insertCard` / `removeCard` / `moveCard`, a retype being an `insertCard` plus a `removeCard` at the index.

Reconciliation is field-scoped. The editor holds its optimistic PM state and re-hydrates a leaf only on an **external** content change (a paste, a `revise`, another edit source), gated by canonical-content equality scoped to that leaf ([CODEC.md](CODEC.md) §Reconciliation). Caret continuity across the editor's *own* edits is the leaf's PM `StepMap`, not a re-hydrate. A by-value leaf, an element or a cell, has no `Addr` to re-hydrate through, so it reconciles against its parent's re-derive (`ProseValue`): a value handed down that moved is read again through `reader.getContentAt` at the leaf's own path, and a read differing from the content the leaf last took, or last committed as the store read it back, replaces its view. Its own commit comes back down the same re-derive and replaces nothing.

**All three lanes report through `onChange`**, carrying an `EditorChange` whose `source` names which one. That the three exist at all is an implementation fact (a prose leaf commits itself and must not bump `revision`, since a re-derive would remount every leaf and cost the caret on every keystroke); that a host has to know it is not. A host recompiling off `onChange` covers prose, scalars and structure with one hook, and reads `source` only to schedule them differently: a structure op happens once per gesture and applies at once, prose and field edits arrive per keystroke and debounce.

`onCaretMove` is the *selection* signal, not a second change signal: it fires on a bare arrow key. The two are separate hooks precisely so following the caret and recompiling are not the same subscription.

**It reports a place, not a transaction.** A leaf dispatches one caret signal per transaction and a transaction need not have moved the caret to exist (a mark toggle over an unmoved range, an anchor op, a plugin's bookkeeping), so a repeat of the place last reported is dropped here rather than in each consumer. The memo is the editor's, not each leaf's, because a place spans leaves: a caret that leaves `main.body` at 5 and comes back to 5 made two moves. What this drops is an edit that reflows the page under a caret holding its offset; a preview answers that from its own recompile, which re-locates the place it is already following (PREVIEW §"Follow-the-caret scroll").

**A content field has two rest forms, and the leaf reads through the schema plane so it never has to ask which.** `doc.getStored` is verbatim: a `richtext` field the editor committed rests as `Content` (what `overwrite`/`applyChange` write) and so does one a bound load conformed (`quill.parse`), a `text` field rests as its literal string after either, while a document that came through the transport door (`Document.fromMarkdown`) rests as the authored string, since nothing has lowered it yet. A body is `Content` either way. The leaf takes `reader.getContent` (`field.ts`, `readLeaf`), which decodes by declared type: `richtext` as markdown, `text` as literal text. Nothing else can tell those apart, and reading one as the other eats every `*` a `text` author typed.

**The commit gate is the rest form, not mere presence.** A `richtext` field not at content rest, unset or the authored string, takes `overwrite` (`opsCommittable`): free, since content-only marks do not survive markdown and an authored string therefore carries no anchors to pay, and it keeps an ordinary first keystroke off the error-recovery path. The first commit lands `Content`, so the authored form is transient and appears on no other path. A `text` leaf asks no gate: its commit is the literal string, which is the rest form already.

## Card operations

- **Add**: pick the kind (a transient menu, skipped when the quill declares one kind), then `quill.seedCard(kind, doc.main.seed?.[kind])` → `insertCard(index, card)` in one mutation. No placeholder card exists before it is real; a seeded card carries the document's `$seed` overlay for the kind, else the kind's `seed:` in `Quill.yaml`, its `$body` included, and nothing else: the overlay replaces the kind's seed whole, every field the block leaves out is absent, and the body is empty where it names none (canon: `CARDS.md`, `SCHEMAS.md` §"Kind seeds and document overlays"). An empty body ghosts the consumer's wording (§"What the surface says"). The strip's add lands the focus in the new card, at its first field, else its body, else its title, once the centring scroll has run, a control's own focus scroll cutting a smooth one short; `insertCard` moves no focus, the host holding the one it means.
- **Reorder / delete**: `moveCard` / `removeCard`, over stable keys. A delete taking the card that visibly holds the focus hands it to the title of the card before, else of the card after, else to the add strip, a title taking it with the caret at its end and nothing selected, since the key that pressed delete may come again: the keyboard's place moves on, and a pointer's press, which some engines leave on the pressed button with no ring, moves nothing. An insert or a removal fades its card where it stands while the cards past it take the reorder's slide (`motion.ts`), so the stack is what moves.
- **Retype**: a card's kind is the one it was added as, and the editor offers no switch for a declared kind (§"Settled and open"). The chrome retypes only a card whose kind the schema does not declare, its way back into the schema, and `setKind` stays the verb for a host that means one. It is `insertCard` of the card under its new kind at the same index, then `removeCard` of the original — that order, since `insertCard` validates the whole card before it mutates and `removeCard` cannot throw, so a refusal leaves the document as it was. The field list re-projects, kept fields keep their content.
- **Rename**: `$ext.editor.title`, editor state that never reaches the backend and the header's first rung (§"Structure mirrors the schema"; canon: `CARDS.md`). It is written once, on blur or Enter; Escape restores the title and writes nothing.
- **Tips**: `$ext.editor.tips` on `main`, a sibling key of `title` in the same namespace: a list of authoring hints a quill or consumer **seeds**, which the editor renders as a dismissable card and never adds to. It is **document-level**, so the channel is `model.tips` at the derive's root, not a field on every card, and it renders in a fixed slot attached under `main`, ahead of the cards, so document-level hints displace no control. Dismissal clears it. Never gates, never renders to the backend, absent when the channel is empty. It draws as a **typewritten slip**: a Courier face and no stroke of its own, over a warmth mixed into that card's own surface, which together say draft where the document says document. Its corners are the card's, so the pair stands in the stack with the silhouette every card has. Its text starts on the prose's edge rather than the card's, and its foot's label ends on that edge at the other side, so a hint reads as a line of the document it is about. That warmth is the surface's one exit from the greyscale that is not a status, guidance being neither an error nor a warning nor focus, and the slip is the only place it is spent — the token chip in a tip and the foot's control under the pointer take it too, so nothing on the card answers in the chrome's neutral. Both are a package decision rather than an eleventh dial: the rungs under them mix over the surface and the ink a consumer already tuned, and the face names a typewriter the platform carries rather than one the package fetches.

**The `editor` namespace is the write unit, and one verb owns it.** `storeExt` replaces the whole `$ext` map, so a writer that stores only its own key destroys every sibling namespace, and a namespace-wide write destroys the sibling keys inside it. Both writers therefore go through `patchEditorExt(doc, addr, patch)` (`ext.ts`), which reads the map, merges, and treats an `undefined` value as a key drop; a consumer seeding the namespace reaches the same verb off `@quillmark/svelte/visual`. That is what keeps a dismissal from wiping every renamed card's title, and what makes key N+1 inherit the rule instead of re-deriving it. A patch that empties the namespace removes it, and `$ext` with it when `editor` was the last namespace — `removeExt` being the one call that drops the map, where `storeExt({})` records an explicit empty one — so a document nothing has renamed or hinted carries no editor slot rather than an empty one. A patch dropping keys the namespace does not have writes nothing.

## Focus and the preview bridge

**One active field holds the focus.** The VisualEditor owns the active address; because leaves are keyed by stable identity, this is plain state, not a value hoisted to a parent to survive remounts. It reports it as an `ActiveLeaf` — the leaf's `DocPath` and its card's session key — for a form control as for a prose leaf: a prose leaf reports through its controller (the source that drives its caret signals too), a control through its wrapper's bubbling `focusin`, which covers an array's N elements and a subform's properties with one handler. The active address is the field's, an `Addr` naming one field and no deeper; the reported path descends to the element or cell the focus is in (`main.contact.email`, `main.keywords[0]`), the address a region and a diagnostic name it by, read off the `data-qm-index` and `data-qm-prop` each container rung stamps on the cell it draws (`stepsTo`). `getActiveLeaf` reaches the controller by that pair, else the by-value prose leaf focused last under that field, and answers `undefined` for a control, which holds no marks for the formatting popover to toggle.

**Every mounted field is a landing target, and the registry is why** (`leaves.ts`). A landing needs a focus and a box to bloom; a prose leaf additionally answers a caret at a USV offset. So the registry holds two lanes behind one lookup: a control lane every field registers into, and a prose lane carrying the codec seam. A by-value prose leaf, an array's element or a subform's cell, is in neither, having no address and sharing its field's key with every sibling: it announces its views on focus into a third lane under that key, where the one focused last answers, which the formatting popover reads and a landing never does. A form control's focus is its own — a date field lands on its first segment, an array on its first element or on the add affordance that is all an empty one has — and it is the same function a click on the field's label calls, so a label and `focusField` cannot land in different places. On a memo the scalar fields are the front matter and the preview reports regions for them (`session.regions()` names `main.signature_block` beside `main.body`), so content-only would cover the smaller half of the bridge.

Both directions ([PREVIEW.md](PREVIEW.md) §Click bridge):

- **preview → editor**: `visualEditor.setCaret(hit)` resolves `hit.field` to a field, which runs `codec.usvToPM(hit.pos)` and sets its PM caret; a `'segment'` hit just focuses the leaf (`hit.pos` is a segment start, not a cluster-exact caret). A form control takes the focus and no caret: the offset is a position in rendered content and a control has no coordinate to spend it in (a numeric input refuses a selection outright, an array's own is an element index the grammar cannot name), so reveal-and-focus is the whole of what a click on plate-placed ink can mean. A landing reveals itself first and waits for the reveal, so it is the one async entry point: a caret placed into a collapsed panel, `inert`, fails silently, and `inert` clears on the render rather than on the ask.
- **editor → preview**: two hops. A caret move in the active leaf emits `onCaretMove(at)` with a `Place` (`/core`): the canonical `DocPath` field address and the USV caret, which is `preview.focusPosition`'s own argument, so the hop is `onCaretMove={preview.focusPosition}` and translates nothing. The editor mints the path off its derived card tree, which already holds every kind, so following the caret costs no `doc.cards` read per keystroke (`doc.cards` serializes every card on each read). The USV `pos` is the shared coordinate: no codec hop.

  `onCaretMove` stays a prose-leaf signal — only a leaf with a caret has one to report — so a focus into any other leaf ends the follow instead, through `onActiveLeafChange={preview.endFollow}` ([PREVIEW.md](PREVIEW.md) §"Follow-the-caret scroll"). The arrival drives both halves of that, because either alone leaves a gap: it also ends the caret memo below, without which a leaf returned to at the offset the memo still names is swallowed, and nothing else restarts a follow that has just ended. A host wiring `onCaretMove` alone gets the sticky slot — a follow nothing ends — so the two are one wiring rather than a hook and an option.

  The two arrive in the order a click's own focus and selection do: the arrival, then the caret in it. `setCaret` holds that order too, which is why it focuses before it dispatches — reporting the caret first would have the arrival end the follow that caret just started.

**A landing in the editor is an event, so the leaf marks it and lets it decay** (`core/bloom.ts`): resting ink would outlive the hop that caused it. Unguarded, because the input is a discrete act — its commonest target is the leaf already focused, where placing a caret changes nothing on screen. The preview marks nothing back: it draws nothing of its own on the page, and correlating the two panes there is unbuilt ([PREVIEW.md](PREVIEW.md) §"Two responsibilities").

**The discrete/continuous split governs the preview's scroll, where it is louder**: a scroll the user did not want takes the pane back. The continuous hop (`onCaretMove`, per keystroke) moves it only when the caret is past the fold; the discrete `scrollToField` centres every time, and ends the follow it outranks ([PREVIEW.md](PREVIEW.md) §"Follow-the-caret scroll"). The round trip closes under that guard rather than against it: a preview click drives `setCaret`, which reports back through `onCaretMove` as a caret move like any other, and the point it names is one the click had on screen already.

**A landing reveals through the leaf's own engine, and the platform's walk is what resolves the scrollport.** The editor owns none of its own — `.qm-editor` scrolls only where the host asked for it with `qm-pane`, and a page-mounted host scrolls the document instead — so a scroll that walks to the nearest scrollable ancestor is the answer to which one moves rather than a hazard to route around. A form control takes the browser's focus scroll. A prose leaf takes a `scrollIntoView`-flagged dispatch, the flag every other caret-placing command in the codec already carries and the reason typing scrolls: unflagged, one leaf answered its two arrival routes differently, and the caret an arrow key revealed was left off screen by the click that placed it (PM focuses with `preventScroll`, so nothing else was going to move). **The trip is the minimum and stops a line clear of the fold, never a centring**: a landing's commonest target is the leaf already focused, and centring would take the pane back on every one of those. The clearance is the caret's alone — it is there so the next line typed does not land past the fold — so the placement rung, having no caret to keep usable, reveals the leaf's box the way a control reveals its own.

## Teardown

One order, held by every surface: **unregister, cancel, then free**. Nothing new resolves through a surface on its way out, the work already scheduled is dropped before what it would have touched, and what both were holding is released last. `core/teardown.ts` carries it as a `Lifespan`: a surface builds one, registers its cancellers in the order they must run, and ends the span once, rather than writing the sequence out at each exit.

Deferred work is why it is an order at all. A continuation crossing an `await tick()` — `setCaret` (reveal, flush, then land the caret in a leaf it looked up before it), `scrollCardIntoView` (flush, then resolve an id and scroll a card), the focus a card's add or delete hands on, an array field's post-commit focus — can find a destroy landed in that window, and act on a surface that is gone. Not a use-after-free: past the flush each touches a captured controller and the DOM, and a selection-only transaction never routes to a commit, so no handle is reached. What it is, is a dispatch into a destroyed ProseMirror view, or an export called on a destroyed component: a throw in a continuation nobody catches. Each site asks `span.resumes(tick())` and drops out, rather than checking a flag it captured before the await.

A document swap arrives as a destroy (leaves and card ids seed once, so a swap remounts), which is what makes one span cover both. Coalescing a surface already does sits inside it and answers a different question: `scrollCardIntoView`'s ticket says whether this continuation is still the current one, the span says whether there is still a surface to act on. A ticket rather than the id it is scrolling to, because two mutations inside a tick can be about the same card — an insert and then a move of it — and under an id both continuations see their own, so the first serves its `center` where the last asked for `nearest`.

That continuation waits out the reorder's trip before it measures anything: `animate:reorder` holds the slot at its pre-move position for the length of the run (`motion.ts`), so a scroll asked for at the flush reads the box the card is leaving. The trip is what says the card moved, and the scroll follows it to where it landed.

## The document swap

`VisualEditor` is a door over `VisualEditorInner`, and the door's whole content is `{#key doc}`: a consumer hands it a different document and the editor remounts under it. The split exists because the state a swap invalidates is not one field. Composable cards key on session id and would re-mount unprompted, the main card is keyed on nothing, and each prose leaf mounts once per stable leaf key with `createField` closing over the `doc` it was handed — so an unkeyed swap leaves the main card rendering and committing to the previous document with every id and index still agreeing. Reseeding by hand means threading a generation token through every leaf key and resetting the id state, the commit-error map, the active address, the leaf registry, the card refs and any pending scroll, which is a remount written out one field at a time. The `{#key}` writes it once.

`quill` is deliberately outside the key: the schema is re-read on every derive, so a quill swap re-projects correctly and keying on it would discard a card tree that needed no rebuilding. What a re-derive cannot do is re-mount the leaves, so a quill swapped without its document reports `rebind-ignored` at `dev` severity. `Preview` reports the same code, and not for `session` alone: the paint loop owns scroll position, mounted slots and an observer set that a remount would discard on every apply, so every prop `createPreview` closed over (`session`, `margin`, `onPick`, `onError`, `strings`) is once-bound, the swap stays the consumer's `{#key session}`, and one guard over the set is what stops it being silent. A guard over one prop of a set is worse than none: a consumer who learns the surface complains when it ignores a prop reads silence on the rest as reactivity. `core/rebind.svelte.ts` is the one copy. It snapshots the mounted identities on its own first run and reports through the `onError` it bound, so the report of a swapped handler reaches the handler that was replaced.

## Chrome

Editing chrome is thin and **per-leaf**; structural chrome is Svelte in the shell.

- **Formatting**: a selection toolbar over the active leaf in the content mark vocabulary (`strong`/`emph`/`underline`/`strike`/`code`/`font_family`/`link`), emitting PM transactions the codec lowers to `markOps`. A keymap mirrors the marks (`Mod-b`/`i`/`u`, `Mod-Shift-x` for `strike`, `Mod-e` for `code`). `Mod-k` is a press of the `link` button: it raises the prompt wherever the button stands and is left to the browser wherever it does not, and it is the surface's own key, a document `keydown` the leaf's keymap leaves unclaimed. **It answers a selection, never a pointer.** A press holds it down until the release, so a drag is not covered by the surface it is about to raise, and a selection no press made raises it once it stands still (`SETTLE_MS`, `FormatPopover.svelte`), so a Shift-arrow run raises nothing until it stops; it hangs off the box the highlight paints rather than off either end of the range, a selection that wraps having its two ends on opposite sides of the block. Whitespace alone raises nothing: every mark over it is invisible. **A `text` leaf raises nothing at all**: it mounts a schema declaring no mark types ([CODEC.md](CODEC.md) §Inline mode), and the surface asks the view it would act on rather than the leaf that registered it, so it withholds itself over one exactly as it never rises over a form control. **An embedded `richtext` leaf raises it as a field's does**: an array's element and a subform's cell, in an open row, a field-level subform or a table, are reached through their views, and a toggle commits by value as a keystroke there does. **`anchor` has no button anywhere.** An anchor is zero-width and draws nothing, so a press would change nothing on screen; the button waits on the comment threads an anchor is for, and no host option draws it. The mark, the field seam that mints one (CODEC §Seams) and the strings keys stay. A held by-value leaf announces nothing, so the read-only text it draws raises nothing. **The buttons carry no applied state.** They are verbs, and a run may carry a mark over part of itself, which a two-state button has no third face for. **`link` carries a value, so its button is a prompt rather than a toggle** (`visual/links.ts`): raised whatever the selection holds, seeded with the href it already carries — the only place the document's own URL is legible — and carrying the remove arm, so the button never means two things. The prompt takes its own focus, the popover being open already by the time it is drawn, and writes to the view it was raised over: a cell view that gave the prompt its focus is no longer the leaf's `focusedView`. A typed value is an href only after normalization: no scheme names a host, which stored verbatim is a relative link resolving against whatever page the editor is embedded in, so it takes `https://` (or `mailto:`, a bare address being the one shape the host prefix would misread). Rooted values (`/`, `#`, `?`, `//`) ask for the embedding page on purpose and are left alone. Writing spells the mark ops out rather than calling `toggleMark`, which matches by mark type and so removes a link where a second href is meant to replace it. **A font family is a pick from the host's library** (`visual/fonts.ts`). The library is the app's, not the quill's: a host builds its engine with `fonts` and hands the editor `engine.fontFaces(quill)` as its `fonts` prop, the families a mark may set, which the editor registers with the page while mounted so a run draws in the face the preview sets it in. A collection's faces past its first are left out of that, a CSS face drawing a collection's first alone, so such a family draws in the root face here and in its own on the page. The picker draws where the leaf declares the mark and there is a family to offer or one under the selection to clear, listing the library's families and the selection's own where the library lacks it, so the picker always shows what the document says; its default sets none and the text takes the surrounding face. Like `link` the mark carries a value, so a pick spells its ops out rather than toggling, and a selection setting two families reads as neither. **Over a leaf that holds lists, two more buttons number or bullet the selection** (`codec/list-toggle.ts`), the Docs chords `Mod-Shift-7` and `Mod-Shift-8` binding the same command in the leaf's keymap, where a caret is a selection of its own line. A line is a textblock the selection touches, a fence excepted, and one ending at the head of a line has selected nothing in it. A line carries a marker where it opens its item; a continuation line goes with its item where the item's opening line is selected too, and carries none of its own otherwise. Where every line carries one of the kind, those markers come off and no others: the items lift out of their list, which closes around them and counts its tail from 1, the split the line-out key makes; in a sub-list the lines stay as the parent item's continuation lines, the place a marker coming off leaves them. Otherwise every line becomes the kind: a run of plain lines is wrapped one item a line, a run of continuation lines opens a sub-list of the kind under its item, as the shorthand at a continuation's head does, the item keeping its marker, a list of the other kind is retyped whole as the shorthand retypes it, and the lists of the kind this leaves touching are one list, so a selection's lines count as one.
- **Input rules**: the markdown shorthands are PM input rules over the block commands the slash menu runs (`codec/blocks.ts`, `codec/inputrules.ts`), producing ordinary transactions; markdown is an input *shorthand*, never the stored form. **Backspace on the press right after a rule fired takes it back**, leaving the text it consumed: a shorthand guesses at what was typed, and the next key is where a writer who meant the literal `# ` says so. A slash pick is a command chosen by name, not a guess, and takes no such undo. **The fence fires on Enter**, at the end of a paragraph reading ` ``` ` and the language after it, which the code block keeps: on the third backtick the language is not typed yet. It is the one shorthand that waits for the line, and Backspace on the press after takes it back like the others. **A typed URL links on the space that closes it**, the link a URL pasted over a selection makes, a bare `www.` read as `https://`. A rule that opens a block at the end of a body mints the paragraph after it (`---`, the fence), for the reason a block island does: the block would otherwise leave nowhere to type, and a code block is the one of them no gap cursor will sit beside. **A rule declines only where what it mints is unrepresentable or is a shape another gesture owns — never on how a quill renders it.** What a quill typesets is not knowable here — a quill this build has not seen declares its own plate — and a construct `importMarkdown` produces must stay authorable or a document opens carrying a shape the editor refuses to make. So one rule answers otherwise, a list shorthand at the head of an item that already exists, where a wrap would mint an item whose only content is another item and Tab nests under the previous sibling instead: there the shorthand is the item's. On a list's first item it retypes the list, every item with it, `1. ` numbering bullets and `- ` bulleting numbers, and `N. ` sets where the list counts from, back to 1 included. On a later item the other kind is a sub-list: the item sinks under the one above, as Tab sinks it, into a list of that kind, or into the sub-list of that kind already standing there, so `- ` in a new numbered paragraph is its first lettered subparagraph and never the whole memo turned to bullets. **A marker the item already shows is taken as typed and changes nothing**: the kind its list already is, any `N. ` on a later item of a numbered list, and `a. `, `(1) ` or `(a) ` at the head of a nested item, the markers a nested level draws. A number comes from position, so a writer typing `2. Second` into the second item meant the number it already shows, and `2. 2. Second` is the one outcome nobody typed for; a number typed midway renumbers nothing. Beside a list of its kind, above it or under it, a list shorthand on a line joins that list whatever `N` is typed: a number comes from position, and `N` is where a list that touches none counts from. Outside a nested item a letter or a parenthesis is no markdown marker and stays text. Backspace on the press after takes any of these back to the text typed. Every other rule fires inside an item: each mints a shape the content holds and `importMarkdown` produces, so what the reference quill makes of one is the quill's to report, not this rule's to predict. No table-entry rule: a pipe row is not a prefix a rule can fire on, and a table is entered from the slash menu instead.
- **Insert menu**: `/` at a word boundary raises the commands over the caret (`codec/slash.ts` owns the model and the picks; `visual/SlashMenu.svelte` draws it). Unlike the one shell-owned format popover, it is the leaf's surface: a trigger belongs to one caret in one leaf, so `ProseField` mounts it beside the view it reads from. Its keys are the leaf's keymap, innermost of the chain, so the caret never leaves the contenteditable the insert is measured against. **The empty line a focused caret holds names the key** (`codec/slash.ts` §`slashHint`, drawn by `prose.css`): a faint `Type / to insert` wherever a `/` would open a menu with something in it, gone with the focus and giving the line to the leaf's ghost where both stand. It fades in once the caret has rested on the line (`--_qm-hint-wait`), longer than the gap between two keystrokes, so typing on through an Enter never flashes it. It is the door's one mark on screen, a pointer door staying declined (§Settled and open). **A command is a name, not a phrase**: one lowercase kebab-case token, drawn as it is typed (`/table`) and completing on a case-insensitive prefix of the name or of any of its words, so `/list` reaches `numbered-list` by the noun a writer has and not only by the word it is distinguished with. A name is not wording, so nothing about it is translated, and the vocabulary is read off the command table rather than kept beside it. **A run outlives its menu.** The run is the trigger's shape — a `/` at a boundary with no whitespace since — where the menu is the shape of the match and draws only over offers, so a backspace off a typo narrows back into the vocabulary rather than deleting through to the bare `/` character by character. Every key reads the offers rather than the run, so an undrawn one swallows nothing and Escape falls to the claimants outside the chain. No dismissal edits text: a space, a caret out of the run, an undo, a blur and Escape over a drawn menu all leave the `/` and what follows it where they were typed, and only a pick edits, consuming exactly the run. **The vocabulary is the block shapes a pick fills**, one command each in `codec/blocks.ts` with the markdown shorthand as its other door, the table's alone reached by no shorthand and the rule's alone left to one: a divider holds no content, so a row for it lands a construct the caret has to step past and `---` is the whole door it keeps. One implementation behind the two, so the second costs a row rather than a second thing to keep true, and the menu is where a writer who has never typed `## ` finds that headings exist. A shorthand is `^`-anchored, so a pick does what the shorthand would have done at the head of the caret's block, the run consumed first, **except a list pick, which runs at any caret in a block leaf**: the head is a prefix's guard, where `- ` firing mid-sentence would eat a dash, and a pick is a gesture at the caret the writer has. At the end of a non-empty block it opens a fresh empty item below it, Enter then `- ` in one gesture; anywhere else it wraps the whole block, the smaller surprise, since a writer who meant to split presses Enter first. In an item's first block a pick is the shorthand's item gesture, so it offers only the other kind there, and at the block's end the list that opens a fresh item opens a sub-list under the text. `subparagraph` is the bullet pick where it puts the line one level deeper under an item, and is offered nowhere else: a memo letters a bullet under an item as a subparagraph, which is the word its writer has, where a bullet outside every item stands at the first level and a bullet pick on a list's first item retypes the list. In a later numbered item it opens the sub-list its name says. **A name is offered only where its command would run**, the menu asking each command rather than restating its guards.
- **Structural keys**: a body leaf's keymap, composed in `codec/keymap.ts` as one *chain* per key, innermost surface first — the `code_block` link (`codec/code.ts`), then the list link (`codec/lists.ts`), then the block-atom link (`codec/atoms.ts`), which is about a neighbour rather than about the surface the caret is in and so answers last: a Backspace at the start of a list's first item is the item's question whatever sits above the list. Ahead of all three is the block link (`codec/blocks.ts`), the exception to that order: it is about the body itself, or about the caret's own line, rather than about any surface either stands in, and a link reading the caret's own surface would answer first and never let it run. **Enter at the very start of the body takes a paragraph above it** where the first block is a code block or a quote: those are blocks no gap cursor will sit beside, two keystrokes on an empty body put one first, and nothing else mints a block there — the document could otherwise never be given a title. A list is not this case: **Enter at the head of an item is a new item above it, the first item included**, wherever the list stands, and the empty first item's own Enter lifts it out to the paragraph a title takes. **An empty first block becomes that paragraph rather than gaining one over it**: an empty item exits its list and an empty quoted paragraph lifts out of the quote, each leaving the single paragraph a caret above needs, where a fence answers with a newline — a line inside the block, in the direction already open — so the block link retypes it and a body opening on an empty fence can still be given a title. **A selection spanning two textblocks is taken before the split**, both in one transaction: upstream's `splitBlock` deletes it inside its own transaction and then reads the default block's fit off the pre-delete document, so a range from the head of a `defining` block into a list retypes a `list_item` to a paragraph and throws out of the keystroke. **Delete on an empty line takes the line**, whatever stands below moving up whole and keeping what it is. Every link below it leaves the line standing: the base keymap joins the block below into it — a list's first item lifted out to fill it and no longer an item, a quote unwrapped into it — and the atom link arms an island for the press after. Upstream takes the line only where the sibling holds the same kind of content, so a heading below it keeps its level where a bullet loses its marker. It declines where the parent cannot spare the block — an empty item, an empty quote, the line being the whole of a construct there — and where nothing follows, a line with no next line being Backspace's. **Backspace edits only its own block.** A press at the head of a block changes that block and nothing beside it: a heading becomes a paragraph, its text kept (the block link), and a list item at its start loses its marker, its text staying where it stands (the list link). **An item's number is its position, and no keystroke writes one.** A later item's blocks become continuation blocks of the item above, a nested first item's the item it is nested in, and the list never splits, so the items below close up: Backspace at the head of the second of three leaves one numbered `1` holding two lines and the third numbered `2`. A top-level first item has no item above and lifts out over the list, which counts from its own `start` again. An empty item is spent, the caret at the end of what stands above it, so Enter then Backspace is the list it was. **Leaving a list takes one rung a press, and only Backspace climbs the last one.** The press after a marker comes off, at the head of a line under a top-level item, takes that line out of the list to full width, the item's lines after it with it: the line loses its indent as it lost its number. It and the list toggle's marker coming off are the gestures that split a list, and the tail counts from 1, a number a split wrote being a stale copy of a position, wrong as soon as an item above it came or went. A line with a sub-list below it in its item stays, since the sub-list would be left with no item, and so does a line under a nested item, whose next rung out is still inside the list; there the press is the ordinary join. The press after a line is out is the join too: a block standing after a list joins onto the list's last line, or moves into its last item whole where one side is a fence. Delete never takes a line out, a forward delete editing the line after the caret and not its indent. **Alt+↑/↓ moves the item** past the one beside it in its list, its sub-items with it, and a selection across items moves them together (`codec/list-move.ts`): the binding an array row and a table line move on. Its number is its position, so the move renumbers and writes nothing else, and at the list's edge the key declines, an item leaving its list being another edit. **Shift-Tab is the outdent and stops at the top level**: a nested item moves up one level, and a top-level item, or a line under one, claims the key and does nothing, as Tab does on a first item, so a press too many while backing out of a sub-list renumbers nothing. **Enter at the head of an unnumbered line that holds text opens an empty unnumbered line above it**, the split a numbered line makes at its head kept to the line, where `splitListItem` would turn the line's text into the next item and leave the empty line under the marker. **Enter on an empty line inside a list takes or gives a marker.** An empty middle item keeps its line as a continuation of the item above, the unnumbered line a writer opens between two numbered ones; an empty continuation line takes a marker back as the next item, or below the list's last item leaves the list, the item it continued keeping its own; an empty last item leaves the list. Enter at the end of a typed continuation line opens the next item. **Delete joins the line below onto the caret's.** At the end of a block in an item, or of the line above a list, the item below loses its marker by the Backspace chain's own link and its first line joins the caret's, the rest of its blocks standing under the joined line; every editor merges two lines on a forward delete, and this is the one seam where the two keys differ, Backspace editing the block it is pressed in and Delete the line after the caret. A fence takes no prose line, so across one only the marker comes off. The caret stays where the key was pressed. A seam inside one item stays the base keymap's, where the two keys already answer alike. An empty item is Delete's exception, the item below moving up into it, since its line is the whole of what Delete edits, and an empty item below is spent; an empty line above a seam is the block link's, which takes the line ahead of this chain: the caret's own line is the nearer fact. **Shift-Enter is a line break, and it is the caret's own line in three different senses** (`codec/breaks.ts`, the break link, behind the code link because a fence holds the nearer answer). In prose it opens a `hard_break`, the `continues` line that keeps one block ([CODEC.md](CODEC.md) §Decode); inside a fence it is the newline Enter already takes, the same command under both keys; **in a heading it is claimed and does nothing**, a heading holding no break ([CODEC.md](CODEC.md) §Decode); a declined key is the browser's `<br>`, the space a heading parses one to. The break takes no marks and the caret keeps them, so a `decode` of what was stored is the document the leaf is already holding and a bold run survives a wrap the author did not mean to end it. **Swallowing is the guard here, not a spelling of declining**: a declined key is the browser's, a contenteditable answers this one with a `<br>` — so a heading, which parses that node to a space, and every selection that is not a text range, claim the key to keep a native break off the leaf. The two surfaces that are one line by construction claim it the same way and for the same reason, beside the Enter each already owns: a one-line `richtext` leaf (`Content::is_inline`) and a table cell, whose newline `normalize` rewrites to a space. Each link declines outside its own surface, so the first to claim a key gets it. A table island's cell traversal is innermost of all and joins no chain: it binds on the nested view, so a keystroke a cell handled never reaches the body's keymap at all (`stopEvent`). **Tab forks on the leaf's role, not the caret's position.** A one-line or `text` leaf is a form field: Tab stays unbound, so field navigation is open for a shell keymap. A body is a document: Tab is structural, and the body holds it wherever no link takes it, Shift-Tab with it: a writer presses Tab to indent, and a Tab that moved the focus would carry the next keystrokes into whatever control took it. **Tab on an unnumbered line sinks that line alone**, the first item of a sub-list of its list's kind, as `- ` or `1. ` at its head makes it, joining a sub-list of that kind right above or below it; sinking the whole item would take its numbered line with it. On a block standing right after a list it moves the block into the list's last item, after what the item holds, the one step in Tab takes an item; a paragraph lands as the item's unnumbered line. **Escape gives the focus up**, the link behind every other, so the browser's next Tab leaves from the body: the slash menu takes Escape ahead of it, and a table cell's climb never reaches it. **No gesture nests a line past the store's bound** of 12 containers, a list item or a quote each counting one (`MAX_NESTING_DEPTH`, `codec/nesting.ts`): Tab there changes nothing, a list or quote wrap, by shorthand or by pick, declines, and a body's plugin refuses any other transaction past it, so a paste or a drop there lands nothing. **Two lists of one kind an edit leaves touching are one list** (`codec/touching.ts`), so the items below count on from the items above, as a run of numbered lines does in Docs and Notion: the line between them taken by Backspace, by Delete or by a selection's delete, and a line numbered beside a list, each join the seam they open in their own transaction. Cleanup is command-local (the primitives join the boundary they open); a global pass would also fuse lists that arrived touching, and an ordinal decrease is how `Content` marks that boundary, so opening a document renumbers nothing. A selection's delete compares the seams around both its ends before and after, and joins only one the delete opened. The atom link exists because the base keymap answers a neighbouring island by deleting it outright: one keystroke, from the paragraph a table insert parks the caret in, with nothing drawn first to say what is about to go. **A press at a fence's edge joins nothing across it.** The base keymap's join there retypes one side's whole text as the other's kind on one keystroke — a fence's lines as prose, or a typed line as code. From inside the fence the press retypes the fence to a paragraph, its own block, `toCodeBlock`'s inverse carrying the text whole with `linebreakReplacement` taking the newlines across as breaks. From the prose beside it the caret steps in, Backspace to the fence's end and Delete to its head, and an empty line under the fence goes with the Backspace. Two fences still join as one, and the code link holds the edge ahead of the list link, so an item's fence is answered the same way. A container's edge is not this press at all: the base keymap moves the whole block in or out there and retypes nothing. **↓ on the last line of a fence nothing follows opens a paragraph after it** (the code link), the way out once Backspace has taken the exit line: a gap cursor will not sit beside a fence, and no block below takes the arrow.
- **Tables / islands**: driven from the PM model, not reconstructed from DOM geometry. An island is one PM leaf node over one content `U+FFFC` slot ([CODEC.md](CODEC.md) §Islands), and a `table` one is a NodeView holding a nested view per cell, on the inline schema plus `hard_break` ([CODEC.md](CODEC.md) §"The table island"), in a field's leaf: a by-value leaf mounts no island view and is held over one (§"Structure mirrors the schema"). It is the one chrome the codec draws rather than the shell: it lives inside the leaf, so it is PM's substitute DOM and not a Svelte component's. That is also why the leaf, not the island, answers "which view holds the caret": the format popover asks the leaf (`focusedView`), raises over a cell exactly as over a body, and withholds only `anchor`, whose coordinate space a cell is not in. The island's own chrome is a band of bars, one cell-rectangle selection and the held column's alignment cluster, all the NodeView's own DOM, so there is no menu channel between the codec and the shell and nothing for the Svelte tier to mount.
- **Structure**: add-card affordance, headers, move/delete/retype controls, panels, over the document mutators.
- **Guidance**: a `description` is a glyph beside the label raising a popover (`visual/FieldHint.svelte`), on hover and on `Mod-/` from the control it describes. The glyph is out of the tab order, so a described field is one Tab stop; the key resolves through the control's own `aria-describedby` (`visual/guidance.ts`), which is also what reaches assistive tech, the popover itself being `aria-hidden`. A table cell's description is its column's, parked once in the header.

**Every floating surface holds a live reference to what it floats over, never a rect measured off it.** The popovers, the menus and the island's grips all hang off something that moves as a leaf scrolls and reflows, and floating-ui's `autoUpdate` tracks a DOM element: it walks the element's overflow ancestors, observes it for resize, and watches it for layout shift. A bare `{ getBoundingClientRect }` unwraps to no element, so three of the four tracking mechanisms are skipped and the fourth recomputes out of numbers taken once. A surface anchored to a range of text has no element and passes a virtual anchor carrying `contextElement` instead (`codec/anchor.ts`), which is what `autoUpdate` walks in an element's place. No rect crosses a state channel, which is what makes the rule hold rather than be remembered: a surface cannot return to a stale one without reintroducing the field. Every floating surface also portals into the nearest `[data-qm-root]` rather than `document.body`, since floating leaves the editor's subtree and the marker is what carries the consumer's dials back to it.

## Diagnostics

Three sources, each routed to a field address and shown inline: `quill.validate(doc)` (`Diagnostic[]` keyed on a canonical `DocPath` `.path`: type errors fatal), the host's `diagnostics` prop, and a local commit error keyed at its known call-site address. Warnings are withheld from every producer that reaches the lane — an undeclared key, a render note a host re-feeds. The label's `*` states required-ness; only errors draw. `quill.validate(doc)` is unchanged at the source: a host reading completeness reads it there, `LiveSession.warnings`, and render errors mapped through `FieldRegion.field`. Routing runs on the boundary's `parseDocPath` (`diagnostics.ts`), resolving the absolute card index to the editor's stable-id keying; a local commit error carries the thrown diagnostic's `code` (0.96 mutator failures carry one). Each set routed to a narrowed or a plain prose leaf also re-hydrates it, re-evaluating its hold (§"Structure mirrors the schema"). Obligation and present-null never gate; a value that fails coercion is the only hard field error (canon: `SCHEMAS.md`).

**A diagnostic draws at the nearest cell the tree holds.** `validate` anchors per leaf, so an object property (`main.contact.email`) and a nested row's cell (`main.appendices[0].entries[1].page`) both arrive deeper than any commit address; each routes to the field it hangs off, `Addr` reaching a root and one field and no deeper, and the field then walks it down (`diagnostics.ts`): a container hands each diagnostic to the cell its next step names and draws at its own foot the ones naming a step it does not hold, and a collapsed row carries its subtree's under its head, where the user can see a row. So a property's draws under its control, a nested cell's under that cell once its row is open and under the row's head until then, a matrix member's under the member; nothing is lost on the way down, and the message still names the leaf. An anchor drops only where its root and first segment name nothing: config-space or malformed, never a document one.

Routing to the field is the editor's call, not Quillmark's: `Diagnostic.path` is precise by contract, the geometry lane keying on the same grammar, and addressability is a fact about `Addr`'s reach rather than the path grammar's. It is §"A nested address is a target through its field" reaching a second consumer, and the walk down is the same steps read by the same rule.

**What a diagnostic says is the consumer's, up to a permanent residue.** `formatDiagnostic(d)` turns a boundary `Diagnostic` into the text under its field; returning `undefined` renders `d.message` unchanged. The formatter reads the whole `Diagnostic`, `args` included: the facts `message` interpolates, keyed by name. What it can re-word tracks what that type carries per lane. **Validation** (`enum_violation`, `type_mismatch`, `format_violation`): the constraint re-words from the quill's schema at `path`, the offending value from `args` (`value`, `sourceToken`, `actual`) and never from the document at `path`. Validation runs post-coercion, so the value the validator saw is the coerced one while the document at `path` holds the authored one, and a consumer reading it back words a sentence about a spelling the user never typed; `args` is Quillmark testifying to what it actually saw, which is the only source that closes the gap. **Edit** (`field_conform`): re-words by a third route, the refused value sitting in neither document (unchanged on throw) nor schema but in the app's own control state, which the app has because it attempted the write. **Parse** (`yaml_error_with_location`, `invalid_structure`): does not re-word. No `path`; `args` names the block (`blockIndex`) and `location` places the failure in the document's own coordinates, so the column, offending key and snippet stay inside the English message: Quillmark prose rides under no key. **Render** (`LiveSession.warnings`): does not re-word. Backend text the editor already treats as an external feed.

The residue is the boundary's shape, not a gap in it: a backend's compile diagnostics are minted from that backend's own message text, an open set no string table can key, and the parse lane's parameters are Quillmark prose, which structuring would launder rather than expose. So the contract is that a product localizes what it can route and the built-in text stands where it cannot. The fallback arm is load-bearing rather than defensive, and `Diagnostic.code` being optional at this pin makes it reachable by type: a formatter switching on `code` hits its default arm on a real payload, not only in principle.

**A diagnostic's displayed text is `message` or the formatter's replacement, and nothing beside it.** `code`, `path`, `hint` and `location` route, count and log; none of them renders. `hint` is the tail of the message it accompanies, so rendering it next to a formatter's replacement ships a two-language diagnostic: a surface that wants a hint puts it through the same formatter and falls back wholesale with it.

**Diagnostics are not the error channel** (`core/errors.ts`). A `Diagnostic` is about the document and draws on the field it belongs to; an `EditorError` is about the surface and draws nowhere: a commit the boundary refused, a card operation that threw, a `validate`/`resolve` that threw, a prose commit that fell back. Every one of them is a path the surface already recovered from, so nothing gates on the handler and an absent handler still logs; the hook exists because a `console.error` is not something an app can route, filter or count. A refused scalar commit produces both, deliberately: the diagnostic pins to the field, the error reaches the sink.

## What the surface says

Every built-in string is a key on `strings`, partial: unset keys take the package's English, so wording is an override rather than a fork. Several are accessible names rather than decoration — an untranslated card control does not read as inconsistent to a screen reader, it reads as the wrong language, which is why this is a seam and not a list of literals to grep for. `bodyPlaceholder` is a key inside the set rather than a prop beside it: the per-card hook and the flat string it falls back to are one decision. An empty body ghosts its resolved `default:`, else the hook's answer, else `bodyGhost` (`resolveBodyGhost`). The body's ghost goes at its first edit, as a field's does: a body edited back to empty holds what the author left, and a ghost there would read as an invitation to a surface already written on. `optionalGhost` is the other ghost the set words, and it words a value rather than an invitation: the `none` an unset optional cell prints. The hook is pure and nothing it returns is cached, so a ghost holds still across a re-derive because the function does: per-card wording is a function of the `cardId` it is handed, per-kind wording a function of `kind`. Determinism is the consumer's to express rather than the editor's to impose.

The strings reach the tree through **context**, not props. They are ambient, read-only and wanted eight components deep, so threading them by hand would put a `strings` prop on every component between the root and each leaf that means nothing to any of them. The channel exposes getters, so a consumer swapping locale mid-session re-renders rather than freezing the wording at mount; a component rendered off-tree falls to the package's English and still has every key.

`Preview` carries its own set for the message states it shows when there is nothing to paint. Separate from the editor's rather than pooled: `/preview` reaches `/core` and nothing editor-side, and a shared strings module would be an edge back across the line that lets it promote to its own package.

## Enum policy

`enumOptionAllowed(addr, value)` marks an enum option unavailable and `enumDisallowed` says how the control draws it: `'disable'` (the default) greys it in place, `'hide'` leaves it out of the list. Both arms exist because **disabled is a promise** — this exists, you cannot use it right now, and there is a state in which you could. That fits an option a deployment withholds, and not one it does not carry at all: a classification level with no such state reads as *ask someone*, which on a compliance surface invites the request rather than closing it.

**Hide-or-disable is a deployment policy, not a per-option judgment**, so it is a prop on the surface rather than a richer verdict from the hook. A listbox where one refused option is hidden and another greyed is incoherent to whoever reads it, and per-option granularity buys no coherent use while inviting that surface. A prop rather than a `strings` key or a dial because it changes what the control contains, not how it reads.

**The selected value is always drawn, disabled when refused.** It is the one genuinely per-option case, and it belongs to the field as an invariant rather than to every consumer's predicate as something to remember: a listbox whose selected value has no row shows nothing for what the document says, and offers no row for the primitive to mark or type-ahead to. Under `'hide'` that row is then the only out-of-policy one in the list, which is what makes the state legible rather than merely shorter.

**The blank is the boundary's, and the control mints none.** Every enum accepts `""` beside its `values:`, the field's spelling of explicitly-nothing (canon `SCHEMAS.md`), and the unset sentinel does not write it: an unset field re-reads the `default:` at every render, where a stored blank is a value that outlives the schema's answer. A document arriving with one draws on the closed control as the quill's `ui.blank_title`, else the em dash, unghosted, and marks no row; an unset field that renders the blank, its `default:` blank or absent, ghosts under the same label. The list offers the choices the schema declares, and the blank is never one.

The pair threads by prop, not through a context the way the wording does (§"What the surface says"). One leaf reads it (`EnumField`), and the predicate is bound per field on the way down regardless, so a context would carry half a feature past the two components already hand-carrying the other half.

`Addr` names a field, so the hook reaches a field's own enum control and stops there. A property inside an object subform has no address to pass, and calling the predicate with the parent field's would key policy on a field+value pair that does not identify the option; those enums are offered whole. A variant's discriminant *is* the field's own control and takes the policy; the cells under it are subform properties and are offered whole, by that same rule, as are a matrix's columns. An enum-typed array element takes the text control (`ArrayField` draws a prose leaf, a subform — as an open row or as a table's cells — or a text input, and nothing else; an `object` element's enum cells are subform properties and are offered whole by the rule above), so there is no listbox for a policy to apply to.

## Enum variants

An `enum` declaring `variants:` rests as a container, `{value: <member>, …that member's fields}` (canon `SCHEMAS.md` §"Enum variants"), and draws as the discriminant's select with that world's cells beneath it. The cells are the object subform unchanged: a variant's cell set is a scalar field set keyed by name over a container the parent commits by value, which is what that component already is. It takes the whole container as its value and the world's declaration as its properties, and hands back the container with one cell written — so cells outside the drawn world ride through untouched and nothing needs a second implementation.

**The drawn world is the one the document renders as**: the authored discriminant, or the *ghosted* `default:`'s member while unset. Reading it through the ghost rather than showing nothing is what keeps the form honest — an unset field resolves its `default:`, so a defaulted world whose cells were hidden would print answers the form never asked for. The blank owns no world, and neither does a member declaring no cells; either draws the select alone.

**A flip keeps the other worlds' answers, and so does clearing.** The boundary carries an answer its world does not select and warns `validation::out_of_variant` rather than dropping it, precisely so that pick-a-world → fill → flip to compare → flip back costs nothing; a control that dropped them would spend exactly what Quillmark went out of its way to keep. Clearing is the discriminant *cell's* own gesture for the same reason: it takes that cell and leaves the answers. A container left holding nothing is an unset field and removes, so the `default:` resolves at render rather than a `{}` being written — the unset rung every scalar control shares.

**A stranded answer is held but undrawn**: the cells of a world that is not live have nowhere to render, and `out_of_variant` is a warning, which the inline lane does not carry (§Diagnostics: errors only). It reads off `quill.validate(doc)` — the lane obligation is already on — where a host that wants to surface one finds it.

**A cell is labelled as a field is**, at every rung: a variant's cell and an object property draw `FieldLabel`, the component every other label on the surface draws, so its name is a real `<label for>` its control is reached by, and its `description:` raises the same guidance affordance. A property borrows the field's id space one `-p-` segment down (`domid.ts`) rather than minting a second, `Addr` reaching a root and one field and no deeper.

**`ui.compact` is inert everywhere a variant carries it**: on the field, whose height is the live world's cell count and so moves on a pick rather than only with the document, and inside it, the cells being the object subform's own grid, which reads no `ui`.

The field commits whole and holds no per-cell write address, `Addr` reaching a root and one field: a diagnostic anchored at `main.<field>.<cell>` routes to the field that draws it, exactly as an object property's does (§Diagnostics). A variant stands at a card's own field list or at a typed dictionary's property, which the object subform draws at the next rung as it draws any container; an array element, a matrix column and another variant's cell refuse one at load (`quill::variant_placement`). Its cells may be containers of their own, drawn at the next rung.

## The matrix

A `matrix` is a vocabulary someone ticks (canon `SCHEMAS.md` §Matrix): a cell whose value is the held set, each held id mapping to an `object` of the field's `properties`, the columns. The boundary hands over the roster alone — `QuillFieldSchema.members`, one flat `{id: title}` mapping in declaration order — and `open`, and the object a member is is derived at parse and not serialized, so the control composes it from `members` × `properties` here (`matrixMemberSchema`), an added item's with a one-line `title` text cell besides (`MATRIX_TITLE`, which the boundary exports no constant for).

**The roster is one list, each member a real checkbox.** Members stack one to a row in declaration order, or, under `ui.compact`, stand abreast in reading order at the count the section's track ladder gives the width (`.qm-tracks`), a held member's columns unfolding inside its own track; each is an `<input type="checkbox">` whose checked state is the member's presence, with its title as the `<label for>`, an unheld member reading at the label ink and a held one at the value ink. A held member unfolds its columns beneath its title, the object subform over the matrix's `properties` at the member's key (`contentAt([id, …])`), the way a variant unfolds its cells; zero columns is a checklist and unfolds nothing. The label row carries the count (`12 of 27 held`) where an array's add chip sits, so the control owns its label row as an array does. The keys are a checkbox group's, not a listbox's: every tick is a tab stop, Space toggles it, and Tab reaches a held member's columns before the next tick. The arrows walk nothing — a compact roster stands abreast with no one axis for ↑/↓ — so Alt+↑/↓ reaches the row around a nested matrix.

**A member is held by being present.** A mapping is held whatever it carries, `{}` included, and a bare scalar is the tick itself: `matrixHeld` reads it as Quillmark's coercion does, `false`, `0`, `"false"` and `null` unheld and every other present scalar held, so a spelling Quillmark refuses still draws the tick it claims and can be unticked from here. A stored `held` is `validation::held_stored` and draws under its member like any diagnostic; the member it sits in reads held, and the columns the control reads leave it out (`matrixColumns`), so the member's next edit writes it back without it. The write lands on the edited member alone: a tick writes the member's columns, or the bare `true` where it answers none, and an untick removes the member. **The document keeps no answer for a member it does not hold**, so the control keeps an unticked member's columns itself, for this mount, and a retick restores them. Every other member rides through as the document spelled it. A map left holding nothing commits the field's empty answer (`matrixEmpty`): the unset field where unset prints nothing held, and `{}` where a `default:` or an optional `matrix?` would print something else, an authored `{}` outranking both. A column emptied writes what its control writes at a field (§"The commitment ladder"), and a held member emptied of every column stays held.

**A default is what prints.** A matrix takes a `default:`, the held set an unset field prints, and the control draws that set at the default rung (`data-default` on the roster, as an array's rows), its content columns read off the literal. The first gesture writes the whole set with the change in it.

**An open matrix's added items follow the roster**, in id order, as the plate prints them (`addedItems`): a key off the roster spelled as an id whose mapping carries a `title`. Each is held by being present, so it draws a fixed tick, its `title` as an input, a remove, and the columns a member draws. At rest the row reads as the roster's rows: the title's text stands where theirs does with no well under it, and the remove recedes until the row holds the pointer or the focus, as an array row's does. Its id is minted once from the title it was added under (`addedId`), snake_case and past every id the roster or the document holds, and a retitle leaves it there: the id is the wire's and never drawn. A title the list already carries, in any spelling, is a second item under its own id, which Quillmark admits. Any other key off the roster is Quillmark's `enum_violation`, drawn nowhere but its diagnostic, at the field's foot, and ridden through.

**The add box adds what is typed.** An open matrix ends in a plain text input (`MatrixAdd`), resting as the add chip it stands in for and taking its well under the pointer, the focus or typed words. Enter adds the words, trimmed, as a new item's `title` and clears the box. The caret lands in the new item's first column; a checklist's item has none, and the caret stays in the box for the next. Enter adds nothing where the box holds nothing but whitespace, and Escape clears it.

Commit is whole, the sparse map through one `writer.set`. Diagnostics anchor per member (`main.checks.fonts.note`) and walk down to the member and its column (§Diagnostics). **A landing focuses what its address names, and nothing else**: a member's own address is its tick, and an added item's, and its `title` cell's, is its title input; a column address focuses that column where the item is held and its columns drawn, and the tick where they are not — the address names the column, and the tick is what would open it. One rule keyed on the address, never on the document, so one address lands in one place, and a preview click on a row the plate claims at the member's address lands on its tick. `ui.compact` never packs a matrix beside a neighbour: its height is the roster's, and grows under every member ticked open, so the hint reaches the roster instead.

## Surface

Two layers, per [ARCHITECTURE.md](ARCHITECTURE.md): the prose leaf is the vanilla-TS core seam, the composition is Svelte chrome.

**The core seam is one prose leaf**: `createField` mounts one into a container over an `Addr` — field-less for a body — and hands back the `FieldController` the composition places a caret through, re-hydrates, and destroys (`core/codec/field.ts`, both re-exported from `/visual`). The leaf owns the codec, the PM view and its plugin stack. Which schema an option selects is §"Structure mirrors the schema"'s, and what each hook reports is §"Edits are ops to the live Document"'s.

```svelte
<!-- chrome: renders the card tree, mounts a <ProseField> (createField) per
     content leaf and a form control per scalar field. -->
<VisualEditor
  bind:this={visualEditor}
  {doc} {quill}
  onActiveLeafChange={preview.endFollow}    <!-- ({ field, cardId }) for a host that reads it -->
  onCaretMove={preview.focusPosition}
  onChange={(change) => change.source === 'structure' ? recompileNow() : schedule()}
  onError={(err) => …}
/>
<!-- bridge in: visualEditor.setCaret(at) from preview.onPick -->
```

The instance surface, reached by that `bind:this`:

```ts
setCaret(at: Landing): Promise<void>;          // preview → editor; a caret where the pick has one
focusField(field: DocPath): Promise<void>;     // any mounted field: reveal + focus, no caret
insertCard(kind: string, at?: number): CardId | undefined;  // the new card's key
removeCard(cardId: CardId): void;
moveCard(cardId: CardId, dir: -1 | 1): void;   // one slot; a no-op at either edge
setKind(cardId: CardId, kind: string): void;
```

**The verbs are the card header's own, and the door is the point.** A host toolbar, command palette or shortcut wants what the chrome has, and every call reports through `onChange` exactly as the click does, so a host that recompiles off the hook needs no second path for its own gestures. They speak the public vocabulary — a `CardId` for a card, a `DocPath` for a place — so a host drives them with what the hooks handed it, and a `bind:this` held across a document swap keeps working: the door delegates to the live mount, so a call landing between a swap and the incoming mount is a no-op.

A target the surface does not hold — a `cardId` from a previous session or an already-removed card, or a path naming no declared field — is a no-op reporting `target-unknown` at `dev`. `setCaret` reports it too, being the verb a preview click drives: a landing that resolved nothing is otherwise indistinguishable from one that landed, and a consumer wiring the bridge reads the difference off nothing else. It is not how the preview answers for a field it places nothing for ([PREVIEW.md](PREVIEW.md) §"Follow-the-caret scroll"): that is a compile answering honestly, not a contract violated.

**A nested address is a target through its field.** The boundary mints `main.keywords[0]`, `main.contact.email`, `main.appendices[0].entries[1].label` and `main.checks.fonts.note` — addresses `Addr` cannot name and the registry is not keyed at — so the landing resolves in two rungs: the whole-path parse, which splits the field from the steps past it (`nestedAddrForFieldPath`, an index a number and a key a string, the `PathStep[]` grammar `reader.getContentAt` walks), then the steps checked against the schema rung by rung (`schemaAt`): an index under a declared array, a key under a declared object, a member and its column under a matrix, a cell of any world or the discriminant under a variant. The reveal is the field's (a panel holds it), and the walk is a call on the field's control (`focusPath`), each rung resolving its own step at the call — an index to a session id, a key to a mounted cell — opening what it names, and handing the rest to the control it opened, the same "resolve only at the point of use" discipline every write takes. Per-element registry keys would be positional keys in a registry whose whole doctrine is dodging positional churn, restaled by every splice above them.

The second rung is the editor's because the editor holds `quill.schema`: a step under a *declared container* is checkable here and nowhere else. Truncating at the preview would be worse than guessing — `pos` is an offset into the leaf's own content, so rewriting the field to `main.keywords` yields a payload that typechecks and mis-addresses. A step the schema does not declare is a `target-unknown`, whatever the tree happens to hold.

**The walk carries a place, not a focus**, and what a place means at its end is the leaf's — the same reason a control owns its focus. A prose leaf, a row or a cell, takes the offset (`ProseValue.setCaret`, `createField`'s body over the view it owns); a collapsed `object` row opens and hands the rest of the walk to the subform it opened, one flush later, since that subform does not exist until the row has rendered — opening is part of the landing rather than something the user does first, a collapsed row holding no control for a caret to sit in; a scalar cell takes the bare focus, an offset being a position in rendered content and a control having no coordinate to spend one in. An absent `pos` is the placement rung on this lane exactly as on `Landing`, which is where a `'segment'` hit lands, so one rule covers both lanes. The landing is therefore the one thing on the surface that answers after a flush, and `setCaret` was already async for the reveal.

**The wash marks what the address named** (`core/bloom.ts`). A landing at depth blooms the innermost row it opened and not the repeater around it: the arrival answers "here" for a click made in the other pane, and a box wider than the one the click resolved says the field where the pick said the row. So the walk hands its row back with the landing, and the registry's own box — the whole list, a field-level subform — is what a landing on the field, or on a property no row holds, falls to, along with a row the document has since dropped. Every other control is one box, which is the one the registry holds.

## Settled and open

- **Card-instance identity is a session key**: an in-memory id per card, reordered in lockstep with the content and resolved to an index only at the mutation boundary (`structure.ts` `IdSeq`). Identity is the editor's, not the document's: nothing document-side backs it, and it does not survive a reload. It rides every card-naming payload (§"The address is the spine"), so the reorder trap is a host's to fall into only by ignoring it.
- **Layout is schema-driven**: a top-level `object` is a panel (legacy `ui.group` a section), `ui.compact` packs a shared row, defaulting from the type (`structure.ts`); the editor adds no responsive policy of its own beyond the container query that steps capacity (§"Structure mirrors the schema").
- **Reorder is buttons in the card stack, and drag on an `object` row and in the table island**, and the split is what each one costs. A card is a heavyweight block in a short curated set, and ↑/↓ already say everything a drag would. Records and a table's lines are many, small, and ordered by the eye, so the pointer is the gesture that fits, and the drop target is the row or line under it rather than a zone to invent; the handle stays out of sight until the pointer is on its row, two standing arrows on every record being ink a list mostly does not need. A scalar list earns neither (§"Structure mirrors the schema"). Every one carries a keyboard twin over the same op, which is what keeps drag an accelerator instead of the only door: Alt+↑/↓ on a row, as in the island.
- **Undo is per-leaf**: each prose leaf carries its own PM history, in which an edit that moves a block (a split, a join, a wrap, a lift) opens a step of its own (`codec/undo.ts`) and the typing after it joins that step. A document-level undo spanning a structural op plus a prose edit (a coordinating stack above the leaves) does not ship in V1. At depth that means removing a nested row takes its subtree with it and nothing undoes it, on one click of a slab whose keyboard twin already guards against the accidental press.
- **Array/table convergence** is `ui.layout: table`: an `array`-of-`object` of short cells draws as a grid when the quill asks, and as the record list otherwise (§"Structure mirrors the schema"). How far the grid should converge with the richtext table island (a scalar array field vs a body island, similar affordance) is not carried: the two share no DOM, and the table's rows carry the record list's controls rather than the island's grips.
- **Structural keymap**: Enter-at-end-of-body to add a card, Tab between fields: navigation crossing leaf boundaries no single PM keymap owns. Does not ship in V1; it lands as a shell keymap over `activeAddr`, alongside the insert surface. Tab is taken inside a body (§Chrome), so field navigation reaches the one-line and `text` leaves, and a body by its Escape.
- **A code block's `lang` is minted by a paste and by the fence shorthand**: it is carried at every rung — the info string through `importMarkdown`, the line kind, the PM attribute, `data-lang` across the DOM a copy and a paste run through (CODEC §"Markdown at the edges") — and survives an edit anywhere in the field. A `<pre>` that states a language arrives carrying it, so a fence copied off a highlighted page is authored the way every other paste is. The keyboard reaches it at the shorthand: the fence fires on Enter, so the language typed after the backticks is the code block's. A slash command is one kebab-case token, so `code-rust` is not that shape. The fence draws it as a label at the label ink in its top corner, read off `data-lang` (`prose.css`): a value no other rung shows would otherwise leave the screen on Enter and stay out of sight in every fence that arrives holding one. A label names the value and draws nothing of it, a leaf showing *that* a span is code and never a prediction of what paper sets it at, which is `heading.level`'s ground, where the ramp is not drawn: the reference quill sets `raw` and reads no language. The label takes no edit, so the language changes in source mode.
- **A card's kind is fixed once it exists**: the add menu is where a kind is chosen, so a mis-picked kind is a delete and a re-add. Retype stays a card operation for the two places that need it, a card whose kind the schema does not declare and a host's `setKind` (§"Card operations").
- **Touch is not a target**: the surface is held to a pointer and a keyboard. A tap that works, as one on a description's glyph does, is no commitment, and nothing is built for touch alone.
- **Reach the surface declines**: a per-`ControlKind` slot past the dials (the package owns reconciliation, so a slot handing out a raw `value` reintroduces a caret reset in consumer code, invisibly to this repo's tests); a pointer-only door onto the insert picks beside the slash menu; image and figure authoring, which needs an asset story the editor does not have; a kind chip beside a card's title, a kind being fixed once the card exists; and a touch accessory bar.

# Visual Editor

> **Implementation**: `src/lib/visual/`

## TL;DR

The headline WYSIWYG surface over a Quillmark document: the card/field structure, the schema-driven fields, and prose-body editing, and how they compose into one editable tree. This doc owns the **composition**; the per-field content↔ProseMirror translation is [CODEC.md](CODEC.md), the rendered view and its caret bridge are [PREVIEW.md](PREVIEW.md), the live `Document` and WASM boundary are [DOCUMENT_MODEL.md](DOCUMENT_MODEL.md). Grounds on quillmark's document and schema model (canon: quillmark `CARDS.md`, `SCHEMAS.md`, `DOCUMENT_STORAGE.md`) and the WASM edit surface (`Document`, `quill.writer(doc)`, the addressed content verbs).

## Federated, not monolithic

The VisualEditor is a **thin composition layer** over many small editors, not one ProseMirror document spanning the page. The schema is the outline, a Svelte tree renders it, and each content leaf (a body, a `richtext`/`plaintext` field) is a separate sub-document with its own PM state, view, history, and plugins; scalar fields are plain form controls.

The content already stores a document as separate leaves at distinct addresses of distinct types: a card's body, its `intro` richtext field, its `signature_block` array are three `Addr`s carrying three value types. A single PM document would re-encode that schema tree as PM nodes and re-derive every address from tree position, paying a markdown serializer into library internals, a parser that patches token handlers, and a plain-text fallback that destroys structure on the next round-trip. Federation deletes that layer. The editor renders the schema directly and lets each leaf pick its editor by type; it owns structure, control selection, card operations, focus, command dispatch, and diagnostics routing, and delegates the substance (content↔PM to the [codec](CODEC.md), geometry to the [preview](PREVIEW.md), truth and mutators to the [document model](DOCUMENT_MODEL.md)).

## Structure mirrors the schema

The layout is a direct projection of `quill.schema` (`QuillSchema { main, card_kinds? }`, each a `CardSchema { fields, ui?, body? }`) joined against the live `Document`'s payload. The editor performs that schema × payload join itself: there is no engine projection for the editing surface (canon: `SCHEMAS.md`, the editor row of the projection table).

**A card is a list of fields**, rendered in **declaration order** (the `fields` map key order; order is not a `ui` hint), then a body. The body is the field-less content leaf (`Addr {card?}`, no `field`), gated by `body.enabled`. Metadata and body are **one abstraction**: a body is a richtext leaf, a `richtext` field is a richtext leaf, and both take the same prose-field editor and codec, differing only in address form (`{card}` vs `{card, field}`) and prominence. One field list, controls chosen by type: no metadata-vs-body dual mode.

**A control per field type** (canon: `SCHEMAS.md` field table). A content type mounts a prose leaf, `inline:` and `plaintext` narrowing the PM schema it runs ([CODEC.md](CODEC.md) §Inline mode); a scalar takes a form control. An optional cell (`t?`) takes its base type's control, the `?` moving the render floor and nothing else: every read of a type strips it (`baseType`). `array` is an add/remove repeater committing by value. A scalar or prose row is edited in place and holds no reorder: a mis-order in a list of strings is a retype. An `object` row collapses to a summary — a box titled by its first short text cell (a `string`, or an inline `richtext` / `plaintext`, read as its text), else by its indexed name — and opens onto the subform, one at a time, a rung inside the summary that disclosed it: the summary stands for the whole row rather than being a cell of it, so what it unfolds hangs under it, where a variant's cells and a matrix's columns stand beside the discriminant and the tick they are stored with and take the flush edge. Flush here, the row's stroke would be collinear with the box above it and with the sibling row below, and the content of an open row would stand outboard of the chevron that opened it. Stacking the subforms instead would spend that rung once per row rather than once; collapsed, an array of ten records is ten lines and one figure. An `object` row carries ↑/↓ on its head, the card header's own controls at the row's rung, and Alt+↑/↓ from anywhere in the row as the keyboard twin, the nearest row answering, so a press inside a nested row never moves the record around it and inside a nested table or list of strings moves nothing: a record of four cells is not a retype, and a move is one splice of the ids and the values together, so the row keeps its session id and everything mounted under it. A row's controls are slabs over the end of its own box; a table's row carries the remove alone, pinned to the end edge of the box the table scrolls in. An array declaring `max:` disables its add chip at the cap and draws the count beside it (`2 / 3`): a disabled button takes no focus, so the count is the carrier of the promise disabled makes (§"Enum policy"); nothing draws for a document already past the cap, `validation::cardinality` being a warning. An element's control is its `items` type's: a content-typed element mounts a prose leaf, one textblock whatever it declares since Enter is the repeater's, reading through `reader.getContentAt(addr, [k])`, which decodes an element at the codec its declared type names. So what an element rests as — the content object, a `plaintext` literal, the authored string a transport door left — is the boundary's business rather than the row's, and a `plaintext` element carries its own asterisks under the mark-free schema exactly as the scalar field does. The write is the other lane and unmoved: an element has no op address, so the row hands its re-encoded `Content` up and the array commits whole, the typed writer resting it back at the element's own form. `object` is a nested subform over `properties`: a scalar draws its own control and a content property mounts the same by-value prose leaf an element does, reading through `reader.getContentAt(addr, ["motto"])` — the boundary walks `items`, `properties`, a variant's key and a matrix's member alike, so a cell reads at its own codec whatever depth it sits at, and a subform under an open `object` row reads at `[k, "motto"]`. A `richtext` or `plaintext` property declaring no `inline` takes the whole row, on the block schema or the plain one, a track beside it standing in whitespace once it holds paragraphs. A prose leaf is held over content its schema cannot hold: narrowed to one textblock, over anything but one plain paragraph; on the plain schema, over anything upstream's `isPlain` refuses once its marks are set aside, a mark being what decode drops and the next commit heals. The decode joins lines and drops containers and islands, and the first keystroke would write that loss back, so a held leaf draws its content on the block schema, read-only, with a note in its box, and commits nothing. Whether it holds is read off the value it mounts, by upstream's rules `isInline` and `isPlain` (`fitsLeaf`), rather than off a diagnostic: a set routed to a field can predate the value it arrives with, and upstream reports a `plaintext(inline)` value that is not plain as `validation::not_plain` alone. A field judges it at mount and on every re-hydrate (`createField`'s `applyExternal`), which each set routed to it asks for (§Diagnostics), so the re-validation after an external write releases the hold or takes it; a by-value leaf, an element or a cell, judges it as of its mount, which is when it takes its state. A trailing empty line holds no narrowed leaf, the decode joining it at the cost of a space: it is the newline a YAML `|` scalar keeps in a `plaintext` value, which upstream refuses with `trailingNewline`. An `enum` declaring `variants:` is the discriminant's select over that same subform, drawing the cells its world brings into play (§"Enum variants"). A `matrix` is grouped ticks over its roster, columns unfolding under a held member (§"The matrix"). The text-ish types are the model's data-vs-content × open/plain-vs-formatted 2×2 (`enum`/`string` are form controls, `plaintext`/`richtext` prose leaves), and only the content side reaches the codec.

**Controls compose by nesting, and depth is bounded by what is open, not by the schema.** A nested `array`, `object` or `matrix` property mounts its own control at the next rung of the same figure — a subform's vertical one `--_qm-nest` further in — rather than a line pointing at the source view. A repeater inside an open row is collapsed rows again, one open at a time, so an open tour under an open vector is one figure at two rungs, whatever the schema's depth. A nested container takes its subform's full span at every depth (`packable`, one rung in). Commit stays by value all the way up: a row has no op address, so an edit inside a nested row re-encodes the field whole through `writer.set`, exactly as an element does — at depth that is the whole subtree per keystroke in a nested prose cell, the bound the design accepts rather than one it fixes. Provenance stays coarse at depth (a nested cell takes its static `sub.default`; `resolve` carries one rung per field), obligation stays per leaf, and undo stays per leaf: removing a nested row takes its subtree with it.

**Two controls compose by position and recurse into nothing.** An `array` of `object` asking `ui.layout: table` on its own `ui` draws as a table where every cell of the row is short: a `string`, an `enum`, a number, a boolean, a date, an inline prose leaf. A column is a property, identified by where it sits under a header, and each cell is the property's ordinary control with no label of its own, its accessible name the row's and the column's composed. It is the record list's row machine in another presentation — the same ids, splices and landing over rows that are always open — not a second tree, which is what keeps one landing lane. Enter and Backspace ride the cell's own control, so they answer from a text or a prose column, the two that leave those keys free where a select opens its list, a switch toggles and a date segment edits. A table's row holds no reorder: every cell of it is on the line, so a mis-order is a retype as it is in a list of strings, where a collapsed record's cells are folded away. Its remove is the row's last track, pinned to the end edge of the box the table scrolls in, so the one gesture the row keeps never needs a scroll and costs the clip one tap floor. That every column is a leaf is the loader's contract, a container column being `quill::table_column_not_flat` at load; the request to draw a grid is the schema's and the answer is the surface's: a row holding a block prose cell declines it at load width and every width after, since the fallback cannot be a container query (a query cannot choose which components mount) and a row that would stack inside a cell is not a line. Every row of it open, the table stands where an open row's subform stands, a rung inside the field behind the subform's vertical: a header set on the field's own edge at the label's register reads as a row of compact fields, and the stroke is what says the columns are the field's insides. A column floors at the width a control that fills its track stays usable at, and one drawing a switch floors at nothing: a mark is one width at every width, so a boolean's column is as narrow as its own name, where a section's grid and a subform's stand a boolean in a track its neighbours share. Narrower than its columns the table scrolls sideways inside its own box, the stroke, the inset and the remove holding still; nothing measures and nothing remounts. The matrix is the other (§"The matrix").

`ui` hints drive layout, not structure: `ui.group` sections fields, `ui.compact` asks a field to share a row and is granted only where a neighbour packs with it, `ui.multiline` sizes a leaf, `ui.layout: table` asks an array for its grid. A field's top-level `title` labels it. A card's header is its `$ext.editor.title` rename, else its kind's `title`, else its own first short text cell, else the humanized kind (`cardTitle`; canon: `CARDS.md`): a kind that declares `title` names every instance with it, and one that declares none names each from its own values, the rule a collapsed row's summary follows. That header follows its field as it is typed: a `string` commits through a bump, and a one-line prose field, whose lane re-derives nothing, recomputes the header on its own commit and holds it beside the model until the next bump. A kind named before any instance of it exists — in the add menu, in the retype select — reads its `title`, else the humanized kind.

**Layout is CSS's, not JavaScript's.** A section is one grid: `placeFields` (`structure.ts`) gives each field a span and nothing else, a container query steps the column capacity, and fields auto-place into it. There are two spans and no third: a field packs into one column, or takes the whole row. A compact field stranded — nothing packed beside it — takes the row, a lone narrow track reading as truncated against the width it leaves empty, and a shared row being the whole of what the hint asked for. Nothing measures, so there is no observer to loop, no first pass at the wrong capacity, and no resize that remounts a prose leaf. A field spanning a shared row subgrids onto the section's own tracks, so controls in one row start at one baseline whatever a neighbour's label did. A full-span field's subform draws its own vertical and steps its properties one nesting rung in from it, and it is a query container over its own width: its tracks step at the widths a section's do — one recipe, `.qm-tracks` in `controls.css`, so the ladder is minted once — over the width the properties actually get, and a subform three rungs in draws the count its box carries rather than the section's over a box three `--_qm-nest` and three verticals narrower. What a property shares with the field above it is the rhythm, not the edge. A `ui.group` section is a collapsible accordion, and a closed one is `inert` rather than merely clipped ([ARCHITECTURE.md](ARCHITECTURE.md) §Styling): a header announcing `aria-expanded="false"` over reachable focus stops states what its content contradicts.

**A press on a section header keeps that header in the fold.** One open at a time means a press can be carried off the fold by exactly one box — the panel closing above it, since a panel opens under its own header — and the answer is the trip every landing here takes: the minimum, to the nearest edge, never a centring (§"Focus and the preview bridge"). A header the collapse never carries out of view costs no scroll at all; one it would rides up and parks at the edge, which is where a section just opened wants its header, the fold below it being the room its fields unfold into. Holding the header on the line it was pressed on is the stricter rule and the worse one: it pins a press near the foot of the fold there, and opens a section into the screen it is sitting on the edge of. The trip is taken per frame over the motion rung, so both panels keep their animation (`visual/hold.ts`). Scroll anchoring answers none of it: the platform picks its anchor off the layout, and what fills the viewport as a section collapses is that section's own content, whose top never moves. An array's object rows take the same hold on the same shape, one row open at a time under a summary that is the control the press lands on.

## The commitment ladder

**The editor projects the commitment ladder.** Per field: show the authored value; else the `default:` where it prints, held as the control's value and never written back unasked (it lives in the schema); else words about the value. A field the schema obliges is **required** — one declaring no `default:`, obligation being a reading of that absence rather than a key beside it (canon `DOCUMENT_MODEL.md`): the label shows a persistent `*`. One axis, so a held default and a `*` are alternatives: the default that would print if nobody answers is the whole of what retires the ask. A typed dictionary is exempt at its own rung — a namespace declares no `default:` at all, and its cells carry the obligation (§"Enum variants") — and so is an optional cell, which can declare none. The `*` is the whole of what the surface says about obligation: warnings do not draw (§Diagnostics), being a second copy of a mark the label already states, and completeness stays a read the host makes. A field's `description:` rides its label as a tooltip.

**A default that prints is the value, and an edit takes it.** An unset field holds its resolved `default:` as the control's own value — a text or number input's text, a prose leaf's content, an array's rows, an enum's trigger, a date's digits — at the default rung (`--_qm-ink-default`, `theme.css`): near enough to `ink` to read as the answer the render prints, a step off it so it never reads as written. Nothing is written until an edit, which writes the whole value as authored with the edit in it, so tabbing through a card writes nothing and freezes nothing against the next quill version. A keystroke typed and removed pins a default on purpose, and a free-text field whose default prints has no gesture back to it once taken, emptying it being the empty answer (below); the enum keeps its sentinel (§"Enum policy"). What a take writes is what the author declared: an array's literal rows, not resolve's, which completes a record against `items`. A text input takes at its first keystroke; a prose leaf at its first transaction that changes its document or an anchor, `createField`'s `fallback` marking the editable `data-default` until then; an array at any gesture, every one of which commits the whole array; a number at the `change` that settles an edit. A date seats the default as the primitive's value on entry from outside the field, so a segment edit commits a whole date with the other segments the default's, and unseats it on leaving without an edit or on a cleared segment; the primitive re-reports its own value as a segment loses focus, which the field reads as no edit. It does not hold the default as its value at rest, which would read as filled to every path that reads the primitive; at rest the digits are painted into the segment text over an unset primitive instead. A nested cell takes its static `sub.default` the same way (§"Structure mirrors the schema").

**Where nothing prints, a control draws words**, at the label rung: what it says is about a value rather than one. An optional cell (`t?`) unanswered prints `none`, which it ghosts at rest, worded `strings.optionalGhost` wherever a control draws a text ghost (a text or number input, an enum's trigger, a prose leaf); a blank or absent enum `default:` draws `ui.blank_title` (§"Enum policy"); a date with no default draws the primitive's `mm`/`dd`/`yyyy`. An unset `string`, `plaintext` or `richtext` whose `default:` prints nothing — none declared, or a type-empty one, the skippable marker — ghosts its `example:`, at rest and on focus, with no prefix; an optional cell draws it in `None`'s stead while it holds the focus (`exampleGhost`). The default dominates wherever it prints, so an example and a default never contend for one control, and the two rungs keep them apart. A `richtext` example is markdown and ghosts as the text it renders, one block to a line (`declaredGhost`). A subform's, a variant's and a table's cells read `sub.example`; a number, a date, a boolean, an enum and an array take none. An answered cell ghosts nothing, an empty answer printing empty, so a prose leaf's ghost goes at its first edit, which answers the field whatever it leaves behind. `example:` reaches the editor as a ghost and never as a value, a seed committing none (§"Card operations"). An invitation is drawn from a key the blueprint reads (`example:`, `body.example`), so the surface offers no guidance an agent working from the blueprint cannot see; a `ui` key carries no facts. Guidance is per-field **or** document-level, never a third thing hanging off a field: no field carries a tips surface of its own, and document-level hints ride the `$ext.editor.tips` card instead (§"Card operations"): a chrome channel, not a schema key, so it makes no claim about any one field. Nothing gates: an incomplete document edits and renders fine (canon: `SCHEMAS.md` blank-fill render). Completeness is a read of `quill.validate(doc)`, not a gate.

**Emptying a control writes what empty means for its field.** Over a default that prints, a text field and a prose leaf write the empty answer (`""`, the empty content), the one answer that prints empty there, and an array whose last row goes writes `[]`: a user who deletes a default's text never watches it come back. Where unset already prints nothing — no default, a type-empty one, an optional cell — a blank text control commits `undefined`, which the VisualEditor lowers to `doc.removeField(addr)` (the quill-free store lane: an unset writes no value, so no schema lane applies): an obliged field stays unanswered and its example returns, and an optional cell returns to `none`, the way back to unanswered upstream asks an editor to offer (canon `SCHEMAS.md`). A number has no empty answer (canon `SCHEMAS.md`: no uniform "blank, not default" for a non-string type), so a blank number unsets and its input takes the default back; so does a date cleared segment by segment. A text field commits a clear as it lands, an empty answer and an unset over nothing both rendering empty, so no clear flashes the field through its default. `EnumField` gives unset a ghost sentinel option: picking it unsets, picking any value (the default included) writes, so "commit the default" is expressible and shown-never-written stays visible. An explicit empty over a non-empty enum default is a member the quill declares (`undecided`, `n_a`), never the blank (canon `SCHEMAS.md`), so the rule above stops at free text. `BooleanField` is exempt (a switch has no blank), except where it is optional: an unset `boolean?` prints `none`, which neither face says, so its thumb stands at the centre and its role is `checkbox`, the toggle role with a `mixed` state, `switch` reading one as false. A press answers it; nothing returns it to unset. Every numeric commit settles at `change` (blur/Enter): a per-keystroke commit round-trips transient invalid prefixes (`-`, `1.`) through the boundary and flashes a coercion diagnostic the `role="status"` live region announces.

## The address is the spine

Every editable unit is keyed by an address: a content leaf by `Addr {card?, field?}`, a scalar by its `{card?, field}` path, a card by position. One identifier is what `applyChange` targets, what the preview bridge speaks (`ContentHit.field`, `FieldRegion.field`), what a diagnostic routes to, and what Svelte keys the tree on.

But cards are **positional** in the content (`cards[i]`): index-keyed loops, stale-index write guards, reused-component reconciliation, phantom placeholders. So the VisualEditor keys each card *instance* by a **session key** and resolves that key to an index only at the mutation boundary (`moveCard`, `applyChange(addr)`). A reorder is a `moveCard` plus a key reorder; no leaf remounts, no PM instance is re-fed a swapped document, no caret is lost to a swap.

**The key leaves the editor.** No address survives a reorder — `Addr` and `DocPath` are both positional, so a host holding `cards.indorsement[2].from` names a different card after one `moveCard` and is told nothing — so every payload naming a card carries its `cardId` beside the address it already carries: `EditorChange`, and the active leaf. `'main'` is the main card's key, the same token the leaf-key space already spends. A removal carries the key with no address: the index is meaningless once the card is gone, and the key is the only handle left to drop. The tips dismissal carries neither; it is document-level chrome that rides `main`'s `$ext` and names no card.

The parallel array is not a workaround. With no card handle in the document, `cardIds` is not a cache of a document-side truth — it **is** the identity, and there is nothing to reconcile it against. So the editor **owns structural mutation for the session**: the keys track the inserts, moves and removals it performs, and a host that mutates the card array behind it re-seeds the surface rather than expecting the keys to follow. A `cardId` is session-scoped by construction: it does not survive a reload, and a host persisting one is persisting a session key.

### One vocabulary in the hooks

**Paths for places, indexes for structure ops.** Every hook naming a place speaks the canonical `DocPath`: `onCaretMove`'s `Place`, `EditorChange.path`, the active leaf's `field`. It is the grammar `Diagnostic.path`, `ContentHit.field`, `FieldRegion.field` and `session.regions()` already key on, so a host wires the editor to the preview as a pass-through and routes a diagnostic back with the string it was given. `Addr` stays the mutator currency — the document verbs take it, the card verbs take indexes — and `enumOptionAllowed` keeps its `Addr` because it runs per option per derive, where minting a path is a string mint on an address that has one for free.

`/core`'s `fieldPathForAddr` / `addrForFieldPath` are the hop between the two, public and beside the grammar they speak (`cardPath`, the card's own path, is the editor's). `addrForFieldPath` is also the one parse: the diagnostics router reads it rather than keeping a second copy of the walk.

A structure op's path names the card (`cards.<kind>[i]`), not the body leaf inside it: the change is the card. It is minted after the mutation, since an insert's card does not exist in the previous tree and a retype's kind is the previous kind.

**A bare path is never cheaper and sometimes wrong.** A hook carrying a `DocPath` and nothing else would spare a host the sites that parse an index back out, except that the struct carries the path too, so `parseDocPath` is one call under either shape. And it loses where the struct does not: an outline highlighting the active card reads `cardId` directly, where a bare path is parsed for an index that is wrong after the next reorder — the trap `cardId` exists to close.

## Edits are ops to the live Document

The VisualEditor holds the live `Document` (via `DocumentWriter = quill.writer(doc)`) and writes ops at an address: never a markdown string, never a whole-document re-serialize:

- **prose leaf** → the codec lowers each PM transaction to a `ChangeBundle` and calls `doc.applyChange(addr, bundle)` ([CODEC.md](CODEC.md)): the per-keystroke path; anchors rebase. The typed writer's markdown-import `setBody` is *not* it. A `plaintext` leaf is the exception, committing its whole text through `writer.set` (CODEC §Inline mode).
- **scalar / array / object** → the typed writer: `writer.set(name, value)`, or `writer.card(i).set(...)`. Schema-checked; an undeclared name throws.
- **structure** → `insertCard` / `removeCard` / `moveCard`, a retype being an `insertCard` plus a `removeCard` at the index.

Reconciliation is field-scoped. The editor holds its optimistic PM state and re-hydrates a leaf only on an **external** content change (a paste, a `revise`, another edit source), gated by canonical-content equality scoped to that leaf ([CODEC.md](CODEC.md) §Reconciliation). Caret continuity across the editor's *own* edits is the leaf's PM `StepMap`, not a re-hydrate.

**All three lanes report through `onChange`**, carrying an `EditorChange` whose `source` names which one. That the three exist at all is an implementation fact (a prose leaf commits itself and must not bump `revision`, since a re-derive would remount every leaf and cost the caret on every keystroke); that a host has to know it is not. A host recompiling off `onChange` covers prose, scalars and structure with one hook, and reads `source` only to schedule them differently: a structure op happens once per gesture and applies at once, prose and field edits arrive per keystroke and debounce.

`onCaretMove` is the *selection* signal, not a second change signal: it fires on a bare arrow key. The two are separate hooks precisely so following the caret and recompiling are not the same subscription.

**It reports a place, not a transaction.** A leaf dispatches one caret signal per transaction and a transaction need not have moved the caret to exist (a mark toggle over an unmoved range, an anchor op, a plugin's bookkeeping), so a repeat of the place last reported is dropped here rather than in each consumer. The memo is the editor's, not each leaf's, because a place spans leaves: a caret that leaves `main.body` at 5 and comes back to 5 made two moves. What this drops is an edit that reflows the page under a caret holding its offset; a preview answers that from its own recompile, which re-locates the place it is already following (PREVIEW §"Follow-the-caret scroll").

**A content field has two rest forms, and the leaf reads through the schema plane so it never has to ask which.** `doc.getStored` is verbatim: a `richtext` field the editor committed rests as `Content` (what `overwrite`/`applyChange` write) and so does one a bound load conformed (`quill.parse`), a `plaintext` field rests as its literal string after either, while a document that came through the transport door (`Document.fromMarkdown`) rests as the authored string, since nothing has lowered it yet. A body is `Content` either way. The leaf takes `reader.getContent` (`field.ts`, `readLeaf`), which decodes by declared type: `richtext` as markdown, `plaintext` as literal text. Nothing else can tell those apart, and reading one as the other eats every `*` a plaintext author typed.

**The commit gate is the rest form, not mere presence.** A `richtext` field not at content rest, unset or the authored string, takes `overwrite` (`opsCommittable`): free, since content-only marks do not survive markdown and an authored string therefore carries no anchors to pay, and it keeps an ordinary first keystroke off the error-recovery path. The first commit lands `Content`, so the authored form is transient and appears on no other path. A `plaintext` leaf asks no gate: its commit is the literal string, which is the rest form already.

## Card operations

- **Add**: pick the kind (a transient menu, skipped when the quill declares one kind), then `quill.seedCard(kind, doc.main.seed?.[kind])` → `insertCard(index, card)` in one mutation. No placeholder card exists before it is real; a seeded card carries the document's `$seed` overlay for the kind, its `$body` included, and nothing else: every field the overlay leaves out is absent, and the body is empty where it names none (canon: `CARDS.md`). An empty body ghosts the kind's `body.example` (§"What the surface says").
- **Reorder / delete**: `moveCard` / `removeCard`, over stable keys.
- **Retype**: `insertCard` of the card under its new kind at the same index, then `removeCard` of the original — that order, since `insertCard` validates the whole card before it mutates and `removeCard` cannot throw, so a refusal leaves the document as it was. The field list re-projects, kept fields keep their content.
- **Rename**: `$ext.editor.title`, editor state that never reaches the backend and the header's first rung (§"Structure mirrors the schema"; canon: `CARDS.md`).
- **Tips**: `$ext.editor.tips` on `main`, a sibling key of `title` in the same namespace: a list of authoring hints a quill or consumer **seeds**, which the editor renders as a dismissable card and never adds to. It is **document-level**, so the channel is `model.tips` at the derive's root, not a field on every card, and it renders in a fixed slot attached under `main`, ahead of the cards, so document-level hints displace no control. Dismissal clears it. Never gates, never renders to the backend, absent when the channel is empty. It draws as a **typewritten slip**: a Courier face, crisper corners than the card it hangs off and no stroke of its own, over a warmth mixed into that card's own surface, which together say draft where the document says document. Its text starts on the prose's edge rather than the card's, so a hint reads as a line of the document it is about. That warmth is the surface's one exit from the greyscale that is not a status, guidance being neither an error nor a warning nor focus, and the slip is the only place it is spent — the token chip in a tip and the foot's control under the pointer take it too, so nothing on the card answers in the chrome's neutral. Both are a package decision rather than an eleventh dial: the rungs under them mix over the surface and the ink a consumer already tuned, and the face names a typewriter the platform carries rather than one the package fetches.

**The `editor` namespace is the write unit, and one verb owns it.** `storeExt` replaces the whole `$ext` map, so a writer that stores only its own key destroys every sibling namespace, and a namespace-wide write destroys the sibling keys inside it. Both writers therefore go through `patchEditorExt(doc, addr, patch)` (`ext.ts`), which reads the map, merges, and treats an `undefined` value as a key drop; a consumer seeding the namespace reaches the same verb off `@quillmark/svelte/visual`. That is what keeps a dismissal from wiping every renamed card's title, and what makes key N+1 inherit the rule instead of re-deriving it. A patch that empties the namespace removes it, and `$ext` with it when `editor` was the last namespace — `removeExt` being the one call that drops the map, where `storeExt({})` records an explicit empty one — so a document nothing has renamed or hinted carries no editor slot rather than an empty one. A patch dropping keys the namespace does not have writes nothing.

## Focus and the preview bridge

**One active field holds the focus.** The VisualEditor owns the active address; because leaves are keyed by stable identity, this is plain state, not a value hoisted to a parent to survive remounts. It reports it as an `ActiveLeaf` — the field's `DocPath` and its card's session key — for a form control as for a prose leaf: a prose leaf reports through its controller (the source that drives its caret signals too), a control through its wrapper's bubbling `focusin`, which covers an array's N elements and a subform's properties with one handler. `getActiveLeaf` reaches the controller by that pair and answers `undefined` for a control, which holds no marks for the formatting popover to toggle.

**Every mounted field is a landing target, and the registry is why** (`leaves.ts`). A landing needs a focus and a box to bloom; a prose leaf additionally answers a caret at a USV offset. So the registry holds two lanes behind one lookup: a control lane every field registers into, and a prose lane carrying the codec seam. A form control's focus is its own — a date field lands on its first segment, an array on its first element or on the add affordance that is all an empty one has — and it is the same function a click on the field's label calls, so a label and `focusField` cannot land in different places. On a memo the scalar fields are the front matter and the preview reports regions for them (`session.regions()` names `main.signature_block` beside `main.body`), so content-only would cover the smaller half of the bridge.

Both directions ([PREVIEW.md](PREVIEW.md) §Click bridge):

- **preview → editor**: `visualEditor.setCaret(hit)` resolves `hit.field` to a field, which runs `codec.usvToPM(hit.pos)` and sets its PM caret; a `'segment'` hit just focuses the leaf (`hit.pos` is a segment start, not a cluster-exact caret). A form control takes the focus and no caret: the offset is a position in rendered content and a control has no coordinate to spend it in (a numeric input refuses a selection outright, an array's own is an element index the grammar cannot name), so reveal-and-focus is the whole of what a click on plate-placed ink can mean. A landing reveals itself first and waits for the reveal, so it is the one async entry point: a caret placed into a collapsed group's `inert` panel fails silently, and `inert` clears on the render rather than on the ask.
- **editor → preview**: two hops. A caret move in the active leaf emits `onCaretMove(at)` with a `Place` (`/core`): the canonical `DocPath` field address and the USV caret, which is `preview.focusPosition`'s own argument, so the hop is `onCaretMove={preview.focusPosition}` and translates nothing. The editor mints the path off its derived card tree, which already holds every kind, so following the caret costs no `doc.cards` read per keystroke (`doc.cards` serializes every card on each read). The USV `pos` is the shared coordinate: no codec hop.

  `onCaretMove` stays a prose-leaf signal — only a leaf with a caret has one to report — so a focus into any other leaf ends the follow instead, through `onActiveLeafChange={preview.endFollow}` ([PREVIEW.md](PREVIEW.md) §"Follow-the-caret scroll"). The arrival drives both halves of that, because either alone leaves a gap: it also ends the caret memo below, without which a leaf returned to at the offset the memo still names is swallowed, and nothing else restarts a follow that has just ended. A host wiring `onCaretMove` alone gets the sticky slot — a follow nothing ends — so the two are one wiring rather than a hook and an option.

  The two arrive in the order a click's own focus and selection do: the arrival, then the caret in it. `setCaret` holds that order too, which is why it focuses before it dispatches — reporting the caret first would have the arrival end the follow that caret just started.

**A landing in the editor is an event, so the leaf marks it and lets it decay** (`core/bloom.ts`): resting ink would outlive the hop that caused it. Unguarded, because the input is a discrete act — its commonest target is the leaf already focused, where placing a caret changes nothing on screen. The preview marks nothing back: it draws nothing of its own on the page, and correlating the two panes there is unbuilt ([PREVIEW.md](PREVIEW.md) §"Two responsibilities").

**The discrete/continuous split governs the preview's scroll, where it is louder**: a scroll the user did not want takes the pane back. The continuous hop (`onCaretMove`, per keystroke) moves it only when the caret is past the fold; the discrete `scrollToField` centres every time, and ends the follow it outranks ([PREVIEW.md](PREVIEW.md) §"Follow-the-caret scroll"). The round trip closes under that guard rather than against it: a preview click drives `setCaret`, which reports back through `onCaretMove` as a caret move like any other, and the point it names is one the click had on screen already.

**A landing reveals through the leaf's own engine, and the platform's walk is what resolves the scrollport.** The editor owns none of its own — `.qm-editor` scrolls only where the host asked for it with `qm-pane`, and a page-mounted host scrolls the document instead — so a scroll that walks to the nearest scrollable ancestor is the answer to which one moves rather than a hazard to route around. A form control takes the browser's focus scroll. A prose leaf takes a `scrollIntoView`-flagged dispatch, the flag every other caret-placing command in the codec already carries and the reason typing scrolls: unflagged, one leaf answered its two arrival routes differently, and the caret an arrow key revealed was left off screen by the click that placed it (PM focuses with `preventScroll`, so nothing else was going to move). **The trip is the minimum and stops a line clear of the fold, never a centring**: a landing's commonest target is the leaf already focused, and centring would take the pane back on every one of those. The clearance is the caret's alone — it is there so the next line typed does not land past the fold — so the placement rung, having no caret to keep usable, reveals the leaf's box the way a control reveals its own.

## Teardown

One order, held by every surface: **unregister, cancel, then free**. Nothing new resolves through a surface on its way out, the work already scheduled is dropped before what it would have touched, and what both were holding is released last. `core/teardown.ts` carries it as a `Lifespan`: a surface builds one, registers its cancellers in the order they must run, and ends the span once, rather than writing the sequence out at each exit.

Deferred work is why it is an order at all. Three sites cross an `await tick()` — `setCaret` (reveal, flush, then land the caret in a leaf it looked up before it), `scrollCardIntoView` (flush, then resolve an id and scroll a card), and an array field's post-commit focus — and a destroy landing in that window leaves a continuation acting on a surface that is gone. Not a use-after-free: past the flush each touches a captured controller and the DOM, and a selection-only transaction never routes to a commit, so no handle is reached. What it is, is a dispatch into a destroyed ProseMirror view, or an export called on a destroyed component: a throw in a continuation nobody catches. Each site asks `span.resumes(tick())` and drops out, rather than checking a flag it captured before the await.

A document swap arrives as a destroy (leaves and card ids seed once, so a swap remounts), which is what makes one span cover both. Coalescing a surface already does sits inside it and answers a different question: `scrollCardIntoView`'s ticket says whether this continuation is still the current one, the span says whether there is still a surface to act on. A ticket rather than the id it is scrolling to, because two mutations inside a tick can be about the same card — an insert and then a move of it — and under an id both continuations see their own, so the first serves its `center` where the last asked for `nearest`.

That continuation waits out the reorder's trip before it measures anything: `animate:reorder` holds the slot at its pre-move position for the length of the run (`motion.ts`), so a scroll asked for at the flush reads the box the card is leaving. The trip is what says the card moved, and the scroll follows it to where it landed.

## The document swap

`VisualEditor` is a door over `VisualEditorInner`, and the door's whole content is `{#key doc}`: a consumer hands it a different document and the editor remounts under it. The split exists because the state a swap invalidates is not one field. Composable cards key on session id and would re-mount unprompted, the main card is keyed on nothing, and each prose leaf mounts once per stable leaf key with `createField` closing over the `doc` it was handed — so an unkeyed swap leaves the main card rendering and committing to the previous document with every id and index still agreeing. Reseeding by hand means threading a generation token through every leaf key and resetting the id state, the commit-error map, the active address, the leaf registry, the card refs and any pending scroll, which is a remount written out one field at a time. The `{#key}` writes it once.

`quill` is deliberately outside the key: the schema is re-read on every derive, so a quill swap re-projects correctly and keying on it would discard a card tree that needed no rebuilding. What a re-derive cannot do is re-mount the leaves, so a quill swapped without its document reports `rebind-ignored` at `dev` severity. `Preview` reports the same code, and not for `session` alone: the paint loop owns scroll position, mounted slots and an observer set that a remount would discard on every apply, so every prop `createPreview` closed over (`session`, `margin`, `onPick`, `onError`, `strings`) is once-bound, the swap stays the consumer's `{#key session}`, and one guard over the set is what stops it being silent. A guard over one prop of a set is worse than none: a consumer who learns the surface complains when it ignores a prop reads silence on the rest as reactivity. `core/rebind.svelte.ts` is the one copy. It snapshots the mounted identities on its own first run and reports through the `onError` it bound, so the report of a swapped handler reaches the handler that was replaced.

## Chrome

Editing chrome is thin and **per-leaf**; structural chrome is Svelte in the shell.

- **Formatting**: a selection toolbar over the active leaf in the content mark vocabulary (`strong`/`emph`/`underline`/`strike`/`code`/`link`, plus `anchor` identity), emitting PM transactions the codec lowers to `markOps`. A keymap mirrors the core marks (`Mod-b`/`i`/`u`); `strike`/`code`/`link` are toolbar-only in V1. **It answers a selection, never a pointer.** A press holds it down until the release, so a drag is not covered by the surface it is about to raise; it hangs off the box the highlight paints rather than off either end of the range, a selection that wraps having its two ends on opposite sides of the block. Whitespace alone raises nothing: every mark over it is invisible. **A `plaintext` leaf raises nothing at all**: it mounts a schema declaring no mark types ([CODEC.md](CODEC.md) §Inline mode), and the surface asks the view it would act on rather than the leaf that registered it, so it withholds itself over one exactly as it never rises over the input a `string` field draws. **The buttons carry no applied state.** They are verbs, and a run may carry a mark over part of itself, which a two-state button has no third face for. **`link` is the one mark carrying a value, so its button is a prompt rather than a toggle** (`visual/links.ts`): raised whatever the selection holds, seeded with the href it already carries — the only place the document's own URL is legible — and carrying the remove arm, so the button never means two things. The prompt takes its own focus, the popover being open already by the time it is drawn. A typed value is an href only after normalization: no scheme names a host, which stored verbatim is a relative link resolving against whatever page the editor is embedded in, so it takes `https://` (or `mailto:`, a bare address being the one shape the host prefix would misread). Rooted values (`/`, `#`, `?`, `//`) ask for the embedding page on purpose and are left alone. Writing spells the mark ops out rather than calling `toggleMark`, which matches by mark type and so removes a link where a second href is meant to replace it.
- **Input rules**: the markdown shorthands are PM input rules over the block commands the slash menu runs (`codec/blocks.ts`, `codec/inputrules.ts`), producing ordinary transactions; markdown is an input *shorthand*, never the stored form. A rule that opens a block at the end of a body mints the paragraph after it (`---`, the fence), for the reason a block island does: the block would otherwise leave nowhere to type, and a code block is the one of them no gap cursor will sit beside. **A rule declines only where what it mints is unrepresentable or is a shape another gesture owns — never on how a quill renders it.** What a quill typesets is not knowable here — a quill this build has not seen declares its own plate — and a construct `importMarkdown` produces must stay authorable or a document opens carrying a shape the editor refuses to make. So one guard survives, a list shorthand at the head of an item that already exists, where firing would mint an item whose only content is another item and Tab nests under the previous sibling instead. Every other rule fires inside an item: each mints a shape the content holds and `importMarkdown` produces, so what the reference quill makes of one is the quill's to report, not this rule's to predict. No table-entry rule: a pipe row is not a prefix a rule can fire on, and a table is entered from the slash menu instead.
- **Insert menu**: `/` at a word boundary raises the commands over the caret (`codec/slash.ts` owns the model and the picks; `visual/SlashMenu.svelte` draws it). Unlike the one shell-owned format popover, it is the leaf's surface: a trigger belongs to one caret in one leaf, so `ProseField` mounts it beside the view it reads from. Its keys are the leaf's keymap, innermost of the chain, so the caret never leaves the contenteditable the insert is measured against. **A command is a name, not a phrase**: one lowercase kebab-case token, drawn as it is typed (`/table`) and completing on a case-insensitive prefix of the name or of any of its words, so `/list` reaches `numbered-list` by the noun a writer has and not only by the word it is distinguished with. A name is not wording, so nothing about it is translated, and the vocabulary is read off the command table rather than kept beside it. **A run outlives its menu.** The run is the trigger's shape — a `/` at a boundary with no whitespace since — where the menu is the shape of the match and draws only over offers, so a backspace off a typo narrows back into the vocabulary rather than deleting through to the bare `/` character by character. Every key reads the offers rather than the run, so an undrawn one swallows nothing and Escape falls to the claimants outside the chain. No dismissal edits text: a space, a caret out of the run, an undo, a blur and Escape over a drawn menu all leave the `/` and what follows it where they were typed, and only a pick edits, consuming exactly the run. **The vocabulary is the block shapes a pick fills**, one command each in `codec/blocks.ts` with the markdown shorthand as its other door, the table's alone reached by no shorthand and the rule's alone left to one: a divider holds no content, so a row for it lands a construct the caret has to step past and `---` is the whole door it keeps. One implementation behind the two, so the second costs a row rather than a second thing to keep true, and the menu is where a writer who has never typed `## ` finds that headings exist. A shorthand is `^`-anchored, so a pick does what the shorthand would have done at the head of the caret's block, the run consumed first. **A name is offered only where its command would run**, the menu asking each command rather than restating its guards.
- **Structural keys**: a body leaf's keymap, composed in `codec/keymap.ts` as one *chain* per key, innermost surface first — the `code_block` link (`codec/code.ts`), then the list link (`codec/lists.ts`), then the block-atom link (`codec/atoms.ts`), which is about a neighbour rather than about the surface the caret is in and so answers last: a Backspace at the start of a list's first item is the item's question whatever sits above the list. Ahead of all three is the block link (`codec/blocks.ts`), the exception to that order: it is about the body itself, or about the caret's own line, rather than about any surface either stands in, and a link reading the caret's own surface would answer first and never let it run. **Enter at the very start of the body takes a paragraph above it** where the first block is not a plain textblock: a code block, a quote and a list are the blocks no gap cursor will sit beside, three keystrokes on an empty body put one first, and nothing else mints a block there — the document could otherwise never be given a title. It is `paragraphAboveList`'s own argument, which is about the block and not about lists; that gesture narrows to the position it still owns, a list under an island or a rule. **An empty first block becomes that paragraph rather than gaining one over it**: an empty item exits its list and an empty quoted paragraph lifts out of the quote, each leaving the single paragraph a caret above needs, where a fence answers with a newline — a line inside the block, in the direction already open — so the block link retypes it and a body opening on an empty fence can still be given a title. **A selection spanning two textblocks is taken before the split**, both in one transaction: upstream's `splitBlock` deletes it inside its own transaction and then reads the default block's fit off the pre-delete document, so a range from the head of a `defining` block into a list retypes a `list_item` to a paragraph and throws out of the keystroke. **Delete on an empty line takes the line**, whatever stands below moving up whole and keeping what it is. Every link below it leaves the line standing: the base keymap joins the block below into it — a list's first item lifted out to fill it and no longer an item, a quote unwrapped into it — and the atom link arms an island for the press after. Upstream takes the line only where the sibling holds the same kind of content, so a heading below it keeps its level where a bullet loses its marker. It declines where the parent cannot spare the block — an empty item, an empty quote, the line being the whole of a construct there — and where nothing follows, a line with no next line being Backspace's. **A delete across a list's seam is one edit from either side.** Delete at the end of a block inside an item runs the Backspace chain at the head of the block below (`codec/lists.ts`) rather than a second table of cases beside it, so the two keys cannot come to differ over a seam this link reaches and the forward half never reaches the base keymap's `joinForward`, which merges the blocks and leaves the unnumbered continuation paragraph the backward half exists to avoid. It carries the edit and not the caret, which stays where the key was pressed, and declines wherever that chain does: a seam inside one item, and the list's outer boundary, stay the base keymap's, where the two keys already answer alike. An empty line above a seam is the block link's, which takes the line ahead of this chain: the caret's own line is the nearer fact. **Shift-Enter is a line break, and it is the caret's own line in three different senses** (`codec/breaks.ts`, the break link, behind the code link because a fence holds the nearer answer). In prose it opens a `hard_break`, the `continues` line that keeps one block ([CODEC.md](CODEC.md) §Decode); inside a fence it is the newline Enter already takes, the same command under both keys; **in a heading it is claimed and does nothing**, a heading holding no break ([CODEC.md](CODEC.md) §Decode); a declined key is the browser's `<br>`, the space a heading parses one to. The break takes no marks and the caret keeps them, so a `decode` of what was stored is the document the leaf is already holding and a bold run survives a wrap the author did not mean to end it. **Swallowing is the guard here, not a spelling of declining**: a declined key is the browser's, a contenteditable answers this one with a `<br>` — so a heading, which parses that node to a space, and every selection that is not a text range, claim the key to keep a native break off the leaf. The two surfaces that are one line by construction claim it the same way and for the same reason, beside the Enter each already owns: a `richtext(inline)` leaf (`Content::is_inline`) and a table cell, whose newline `normalize` rewrites to a space. Each link declines outside its own surface, so the first to claim a key gets it, and outside every link the key is not swallowed, leaving the body a keyboard exit. A table island's cell traversal is innermost of all and joins no chain: it binds on the nested view, so a keystroke a cell handled never reaches the body's keymap at all (`stopEvent`). **Tab forks on the leaf's role, not the caret's position.** An inline/plaintext leaf is a form field: Tab stays unbound, so field navigation is open for a shell keymap. A body is a document: Tab is structural. Cleanup is command-local (the primitives join the boundary they open); a global pass would fuse adjacent same-type lists, and an ordinal decrease is how `Content` marks that boundary. The atom link exists because the base keymap answers a neighbouring island by deleting it outright: one keystroke, from the paragraph a table insert parks the caret in, with nothing drawn first to say what is about to go. **A press at a fence's edge retypes the fence rather than joining across it.** The base keymap's join there retypes one side's whole text as the other's kind on one keystroke — a fence's lines as prose, or a typed line as code — so a press between a code block and the prose block it stands against turns the code block into a paragraph and joins nothing, from either side, and the press after that is the ordinary prose join. Where either side is empty there is no text to retype and no join to refuse, and the block link's Delete takes the empty line first. It is `toCodeBlock`'s inverse in its place and carries the text whole, `linebreakReplacement` taking the newlines across as breaks. The code link holds it, so a fence inside an item is answered ahead of the list link's merge, which declines across the same edge and leaves the items to the base keymap, merged with each block kept whole. A container's edge is not this press at all: the base keymap moves the whole block in or out there and retypes nothing.
- **Tables / islands**: driven from the PM model, not reconstructed from DOM geometry. An island is one PM leaf node over one content `U+FFFC` slot ([CODEC.md](CODEC.md) §Islands), and a `table` one is a NodeView holding a nested inline-schema view per cell ([CODEC.md](CODEC.md) §"The table island"). It is the one chrome the codec draws rather than the shell: it lives inside the leaf, so it is PM's substitute DOM and not a Svelte component's. That is also why the leaf, not the island, answers "which view holds the caret": the format popover asks the leaf (`focusedView`), raises over a cell exactly as over a body, and withholds only `anchor`, whose coordinate space a cell is not in. The island's own chrome raises nothing: a band of bars and one cell-rectangle selection, so there is no menu channel between the codec and the shell and nothing for the Svelte tier to mount.
- **Structure**: add-card affordance, headers, move/delete/retype controls, group sections, over the document mutators.

**Every floating surface holds a live reference to what it floats over, never a rect measured off it.** The popovers, the menus and the island's grips all hang off something that moves as a leaf scrolls and reflows, and floating-ui's `autoUpdate` tracks a DOM element: it walks the element's overflow ancestors, observes it for resize, and watches it for layout shift. A bare `{ getBoundingClientRect }` unwraps to no element, so three of the four tracking mechanisms are skipped and the fourth recomputes out of numbers taken once. A surface anchored to a range of text has no element and passes a virtual anchor carrying `contextElement` instead (`codec/anchor.ts`), which is what `autoUpdate` walks in an element's place. No rect crosses a state channel, which is what makes the rule hold rather than be remembered: a surface cannot return to a stale one without reintroducing the field. Every floating surface also portals into the nearest `[data-qm-root]` rather than `document.body`, since floating leaves the editor's subtree and the marker is what carries the consumer's dials back to it.

## Diagnostics

Three sources, each routed to a field address and shown inline: `quill.validate(doc)` (`Diagnostic[]` keyed on a canonical `DocPath` `.path`: type errors fatal), the host's `diagnostics` prop, and a local commit error keyed at its known call-site address. Warnings are withheld from every producer that reaches the lane — an undeclared key, a render note a host re-feeds. The label's `*` states required-ness; only errors draw. `quill.validate(doc)` is unchanged at the source: a host reading completeness reads it there, `LiveSession.warnings`, and render errors mapped through `FieldRegion.field`. Routing runs on the boundary's `parseDocPath` (`diagnostics.ts`), resolving the absolute card index to the editor's stable-id keying; a local commit error carries the thrown diagnostic's `code` (0.96 mutator failures carry one). Each set routed to a narrowed or a plain prose leaf also re-hydrates it, re-evaluating its hold (§"Structure mirrors the schema"). Obligation and present-null never gate; a value that fails coercion is the only hard field error (canon: `SCHEMAS.md`).

**A diagnostic draws at the nearest cell the tree holds.** `validate` anchors per leaf, so an object property (`main.contact.email`) and a nested row's cell (`main.appendices[0].entries[1].page`) both arrive deeper than any commit address; each routes to the field it hangs off, `Addr` reaching a root and one field and no deeper, and the field then walks it down (`diagnostics.ts`): a container hands each diagnostic to the cell its next step names and draws at its own foot the ones naming a step it does not hold, and a collapsed row carries its subtree's under its head, where the user can see a row. So a property's draws under its control, a nested cell's under that cell once its row is open and under the row's head until then, a matrix member's under the member; nothing is lost on the way down, and the message still names the leaf. An anchor drops only where its root and first segment name nothing: config-space or malformed, never a document one.

Routing to the field is the editor's call, not the engine's: `Diagnostic.path` is precise by contract, the geometry lane keying on the same grammar, and addressability is a fact about `Addr`'s reach rather than the path grammar's. It is §"A nested address is a target through its field" reaching a second consumer, and the walk down is the same steps read by the same rule.

**What a diagnostic says is the consumer's, up to a permanent residue.** `formatDiagnostic(d)` turns a boundary `Diagnostic` into the text under its field; returning `undefined` renders `d.message` unchanged. The formatter reads the whole `Diagnostic`, `args` included: the facts `message` interpolates, keyed by name. What it can re-word tracks what that type carries per lane. **Validation** (`enum_violation`, `type_mismatch`, `format_violation`): the constraint re-words from the quill's schema at `path`, the offending value from `args` (`value`, `sourceToken`, `actual`) and never from the document at `path`. Validation runs post-coercion, so the value the validator saw is the coerced one while the document at `path` holds the authored one, and a consumer reading it back words a sentence about a spelling the user never typed; `args` is the engine testifying to what it actually saw, which is the only source that closes the gap. **Edit** (`field_conform`): re-words by a third route, the refused value sitting in neither document (unchanged on throw) nor schema but in the app's own control state, which the app has because it attempted the write. **Parse** (`yaml_error_with_location`, `invalid_structure`): does not re-word. No `path`; `args` names the block (`blockIndex`) and `location` places the failure in the document's own coordinates, so the column, offending key and snippet stay inside the English message: engine prose rides under no key. **Render** (`LiveSession.warnings`): does not re-word. Backend text the editor already treats as an external feed.

The residue is the boundary's shape, not a gap in it: a backend's compile diagnostics are minted from that backend's own message text, an open set no string table can key, and the parse lane's parameters are engine prose, which structuring would launder rather than expose. So the contract is that a product localizes what it can route and the built-in text stands where it cannot. The fallback arm is load-bearing rather than defensive, and `Diagnostic.code` being optional at this pin makes it reachable by type: a formatter switching on `code` hits its default arm on a real payload, not only in principle.

**A diagnostic's displayed text is `message` or the formatter's replacement, and nothing beside it.** `code`, `path`, `hint` and `location` route, count and log; none of them renders. `hint` is the tail of the message it accompanies, so rendering it next to a formatter's replacement ships a two-language diagnostic: a surface that wants a hint puts it through the same formatter and falls back wholesale with it.

**Diagnostics are not the error channel** (`core/errors.ts`). A `Diagnostic` is about the document and draws on the field it belongs to; an `EditorError` is about the surface and draws nowhere: a commit the boundary refused, a card operation that threw, a `validate`/`resolve` that threw, a prose commit that fell back. Every one of them is a path the surface already recovered from, so nothing gates on the handler and an absent handler still logs; the hook exists because a `console.error` is not something an app can route, filter or count. A refused scalar commit produces both, deliberately: the diagnostic pins to the field, the error reaches the sink.

## What the surface says

Every built-in string is a key on `strings`, partial: unset keys take the package's English, so wording is an override rather than a fork. Several are accessible names rather than decoration — an untranslated card control does not read as inconsistent to a screen reader, it reads as the wrong language, which is why this is a seam and not a list of literals to grep for. `bodyPlaceholder` is a key inside the set rather than a prop beside it: the per-card hook and the flat string it falls back to are one decision. An empty body ghosts its resolved `default:`, else its kind's `body.example`, else the hook's answer, else `bodyGhost` (`resolveBodyGhost`): the quill's invitation outranks the consumer's, being the one the blueprint carries. The body's ghost goes at its first edit, as a field's does: a body edited back to empty holds what the author left, and a ghost there would read as an invitation to a surface already written on. `optionalGhost` is the other ghost the set words, and it words a value rather than an invitation: the `none` an unset optional cell prints. The hook is pure and nothing it returns is cached, so a ghost holds still across a re-derive because the function does: per-card wording is a function of the `cardId` it is handed, per-kind wording a function of `kind`. Determinism is the consumer's to express rather than the editor's to impose.

The strings reach the tree through **context**, not props. They are ambient, read-only and wanted eight components deep, so threading them by hand would put a `strings` prop on every component between the root and each leaf that means nothing to any of them. The channel exposes getters, so a consumer swapping locale mid-session re-renders rather than freezing the wording at mount; a component rendered off-tree falls to the package's English and still has every key.

`Preview` carries its own set for the message states it shows when there is nothing to paint. Separate from the editor's rather than pooled: `/preview` reaches `/core` and nothing editor-side, and a shared strings module would be an edge back across the line that lets it promote to its own package.

## Enum policy

`enumOptionAllowed(addr, value)` marks an enum option unavailable and `enumDisallowed` says how the control draws it: `'disable'` (the default) greys it in place, `'hide'` leaves it out of the list. Both arms exist because **disabled is a promise** — this exists, you cannot use it right now, and there is a state in which you could. That fits an option a deployment withholds, and not one it does not carry at all: a classification level with no such state reads as *ask someone*, which on a compliance surface invites the request rather than closing it.

**Hide-or-disable is a deployment policy, not a per-option judgment**, so it is a prop on the surface rather than a richer verdict from the hook. A listbox where one refused option is hidden and another greyed is incoherent to whoever reads it, and per-option granularity buys no coherent use while inviting that surface. A prop rather than a `strings` key or a dial because it changes what the control contains, not how it reads.

**The selected value is always drawn, disabled when refused.** It is the one genuinely per-option case, and it belongs to the field as an invariant rather than to every consumer's predicate as something to remember: a listbox whose selected value has no row shows nothing for what the document says, and offers no row for the primitive to mark or type-ahead to. Under `'hide'` that row is then the only out-of-policy one in the list, which is what makes the state legible rather than merely shorter.

**The blank is the boundary's, and the control mints none.** Every enum accepts `""` beside its `values:`, the field's spelling of explicitly-nothing (canon `SCHEMAS.md`), and the unset sentinel does not write it: an unset field re-reads the `default:` at every render, where a stored blank is a value that outlives the schema's answer. A document arriving with one draws on the closed control as the quill's `ui.blank_title`, else the em dash, unghosted, and marks no row; an unset field that renders the blank, its `default:` blank or absent, ghosts under the same label. The list offers the choices the schema declares, and the blank is never one.

The pair threads by prop, not through a context the way the wording does (§"What the surface says"). One leaf reads it (`EnumField`), and the predicate is bound per field on the way down regardless, so a context would carry half a feature past the two components already hand-carrying the other half.

`Addr` names a field, so the hook reaches a field's own enum control and stops there. A property inside an object subform has no address to pass, and calling the predicate with the parent field's would key policy on a field+value pair that does not identify the option; those enums are offered whole. A variant's discriminant *is* the field's own control and takes the policy; the cells under it are subform properties and are offered whole, by that same rule, as are a matrix's columns. An enum-typed array element takes the text control (`ArrayField` draws a prose leaf, a subform — as an open row or as a table's cells — or a text input, and nothing else; an `object` element's enum cells are subform properties and are offered whole by the rule above), so there is no listbox for a policy to apply to.

## Enum variants

An `enum` declaring `variants:` rests as a container, `{value: <member>, …that member's fields}` (canon `SCHEMAS.md` §"Enum variants"), and draws as the discriminant's select with that world's cells beneath it. The cells are the object subform unchanged: a variant's cell set is a scalar field set keyed by name over a container the parent commits by value, which is what that component already is. It takes the whole container as its value and the world's declaration as its properties, and hands back the container with one cell written — so cells outside the drawn world ride through untouched and nothing needs a second implementation.

**The drawn world is the one the document renders as**: the authored discriminant, or the *ghosted* `default:`'s member while unset. Reading it through the ghost rather than showing nothing is what keeps the form honest — an unset field resolves its `default:`, so a defaulted world whose cells were hidden would print answers the form never asked for. The blank owns no world, and neither does a member declaring no cells; either draws the select alone.

**A flip keeps the other worlds' answers, and so does clearing.** The boundary carries an answer its world does not select and warns `validation::out_of_variant` rather than dropping it, precisely so that pick-a-world → fill → flip to compare → flip back costs nothing; a control that dropped them would spend exactly what the engine went out of its way to keep. Clearing is the discriminant *cell's* own gesture for the same reason: it takes that cell and leaves the answers. A container left holding nothing is an unset field and removes, so the `default:` resolves at render rather than a `{}` being written — the unset rung every scalar control shares.

**A stranded answer is held but undrawn**: the cells of a world that is not live have nowhere to render, and `out_of_variant` is a warning, which the inline lane does not carry (§Diagnostics: errors only). It reads off `quill.validate(doc)` — the lane obligation is already on — where a host that wants to surface one finds it.

**Obligation is per world**, which is the axis variants buy: a cell inside a variant reads its own `default:`-presence, so one with no `default:` reads *required in this world* and is silent in every other. The cell draws the field label's `*`, and so does an object property — `validate` anchors obligation per leaf, so a cell inside a container is obliged in its own right while the container above it holds none. The mark means the same thing at that rung and is stated the same way: a property draws `FieldLabel`, the component every other label on the surface draws, so its name is a real `<label for>` its control is reached by, its `description:` raises the same guidance affordance, and the `*` announces the word "required" from inside the label. A property borrows the field's id space one `-p-` segment down (`domid.ts`) rather than minting a second, `Addr` reaching a root and one field and no deeper.

**`ui.compact` is inert everywhere a variant carries it**: on the field, whose height is the live world's cell count and so moves on a pick rather than only with the document, and inside it, the cells being the object subform's own grid, which reads no `ui`.

The field commits whole and holds no per-cell write address, `Addr` reaching a root and one field: a diagnostic anchored at `main.<field>.<cell>` routes to the field that draws it, exactly as an object property's does (§Diagnostics). A variant stands at a card's own field list or at a typed dictionary's property, which the object subform draws at the next rung as it draws any container; an array element, a matrix column and another variant's cell refuse one at load (`quill::variant_placement`). Its cells may be containers of their own, drawn at the next rung.

## The matrix

A `matrix` is a closed vocabulary someone ticks (canon `SCHEMAS.md` §Matrix): a namespace whose keys the roster fixes, each member an `object` of a synthesized `held` beside the field's `properties`, the columns. The boundary hands over the roster alone — `QuillFieldSchema.members`, one flat `{id: title}` mapping in declaration order — and the member object each desugars to is derived at parse and not serialized, so the control composes it from `members` × `properties` here (`matrixMemberSchema`), and `held` is minted here as the second reserved key beside the discriminant (`MATRIX_HELD`), the boundary exporting no constant for it.

**The roster is one list, each member a real checkbox.** Members stack one to a row in declaration order, or, under `ui.compact`, stand abreast in reading order at the count the section's track ladder gives the width (`.qm-tracks`), a held member's columns unfolding inside its own track; each is an `<input type="checkbox">` bound to its `held` cell with its title as the `<label for>`, an unheld member reading at the label ink and a held one at the value ink. A held member unfolds its columns beneath its title, the object subform over the matrix's `properties` at the member's key (`contentAt([id, …])`), the way a variant unfolds its cells; zero columns is a checklist and unfolds nothing. An unheld member's retained columns are held but undrawn, the variant rule: in the document and not on the page. The label row carries the count (`12 of 27 held`) where an array's add chip sits, so the control owns its label row as an array does. The keys are a checkbox group's, not a listbox's: every tick is a tab stop, Space toggles it, and Tab reaches a held member's columns before the next tick. The arrows walk nothing — a compact roster stands abreast with no one axis for ↑/↓ — so Alt+↑/↓ reaches the row around a nested matrix.

**A member has two rest forms, and the read takes both.** A bare scalar is the tick and a mapping is the member object, whose `held` cell resolves as every absent cell does, to its `default:` of `false` — so a stored member is a bare tick, `{held?, …columns}`, or absent, and `{note: x}` is unheld with its note retained. `conform` normalizes, and the control reads the stored payload, which a document through the transport door has never been conformed through (§"A content field has two rest forms" names the hazard). `matrixHeld` reads a present tick as held except where the engine's own coercion reads false — `false`, `0`, `"false"`, `null` — so a spelling the engine would refuse still draws the tick it claims and can be unticked from here. The write lands one form, on the edited member alone: a tick writes `{held: true, …columns}`, an untick keeps the columns under `held: false`, so tick, type, untick, retick loses nothing, and every other member rides through as the document spelled it — the typed writer resting each at the object form is the engine's normalization, not the control's.

**Dropping an unheld blank member is the engine's rule, not a second copy of it.** Which columns are blank is the same reading every other control's unset rung takes (§"The commitment ladder"): a column control that clears to unset drops its key, so a member unheld with no columns left leaves the map, and a map left holding nothing is an unset field; a column whose default prints clears to the empty answer instead, which is a column the member still holds. The editor drops keys it has emptied rather than deciding skippability for itself.

Commit is whole, the sparse map through one `writer.set`. Diagnostics anchor per member (`main.checks.fonts.note`) and walk down to the member and its column (§Diagnostics). **A landing focuses what its address names, and nothing else**: a member address, or its `held` cell, focuses the tick; a column address focuses that column where the member is held and its columns drawn, and the tick where they are not — the address names the column, and the tick is what would open it. One rule keyed on the address, never on the document, so one address lands in one place. `ui.compact` never packs a matrix beside a neighbour: its height is the roster's, and grows under every member ticked open, so the hint reaches the roster instead.

## Surface

Two layers, per [ARCHITECTURE.md](ARCHITECTURE.md): the prose leaf is the vanilla-TS core seam, the composition is Svelte chrome.

**The core seam is one prose leaf**: `createField` mounts one into a container over an `Addr` — field-less for a body — and hands back the `FieldController` the composition places a caret through, re-hydrates, and destroys (`core/codec/field.ts`, both re-exported from `/visual`). The leaf owns the codec, the PM view and its plugin stack. Which schema an option selects is §"Structure mirrors the schema"'s, and what each hook reports is §"Edits are ops to the live Document"'s.

```svelte
<!-- chrome: renders the card tree, mounts a <ProseField> (createField) per
     content leaf and a form control per scalar field. -->
<VisualEditor
  bind:this={visualEditor}
  {doc} {quill}
  onActiveLeafChange={preview.endFollow}    <!-- ({ field, cardId }) for a host that reads it -->
  onCaretMove={preview.focusPosition}
  onChange={(change) => change.source === 'structure' ? recompileNow() : schedule()}
  onError={(err) => …}
/>
<!-- bridge in: visualEditor.setCaret(at) from preview.onPick -->
```

The instance surface, reached by that `bind:this`:

```ts
setCaret(at: Landing): Promise<void>;          // preview → editor; a caret where the pick has one
focusField(field: DocPath): Promise<void>;     // any mounted field: reveal + focus, no caret
insertCard(kind: string, at?: number): CardId | undefined;  // the new card's key
removeCard(cardId: CardId): void;
moveCard(cardId: CardId, dir: -1 | 1): void;   // one slot; a no-op at either edge
setKind(cardId: CardId, kind: string): void;
```

**The verbs are the card header's own, and the door is the point.** A host toolbar, command palette or shortcut wants what the chrome has, and every call reports through `onChange` exactly as the click does, so a host that recompiles off the hook needs no second path for its own gestures. They speak the public vocabulary — a `CardId` for a card, a `DocPath` for a place — so a host drives them with what the hooks handed it, and a `bind:this` held across a document swap keeps working: the door delegates to the live mount, so a call landing between a swap and the incoming mount is a no-op.

A target the surface does not hold — a `cardId` from a previous session or an already-removed card, or a path naming no declared field — is a no-op reporting `target-unknown` at `dev`. `setCaret` reports it too, being the verb a preview click drives: a landing that resolved nothing is otherwise indistinguishable from one that landed, and a consumer wiring the bridge reads the difference off nothing else. It is not how the preview answers for a field it places nothing for ([PREVIEW.md](PREVIEW.md) §"Follow-the-caret scroll"): that is a compile answering honestly, not a contract violated.

**A nested address is a target through its field.** The boundary mints `main.keywords[0]`, `main.contact.email`, `main.appendices[0].entries[1].label` and `main.checks.fonts.note` — addresses `Addr` cannot name and the registry is not keyed at — so the landing resolves in two rungs: the whole-path parse, which splits the field from the steps past it (`nestedAddrForFieldPath`, an index a number and a key a string, the `PathStep[]` grammar `reader.getContentAt` walks), then the steps checked against the schema rung by rung (`schemaAt`): an index under a declared array, a key under a declared object, a member and its column under a matrix, a cell of any world or the discriminant under a variant. The reveal is the field's (a group holds it), and the walk is a call on the field's control (`focusPath`), each rung resolving its own step at the call — an index to a session id, a key to a mounted cell — opening what it names, and handing the rest to the control it opened, the same "resolve only at the point of use" discipline every write takes. Per-element registry keys would be positional keys in a registry whose whole doctrine is dodging positional churn, restaled by every splice above them.

The second rung is the editor's because the editor holds `quill.schema`: a step under a *declared container* is checkable here and nowhere else. Truncating at the preview would be worse than guessing — `pos` is an offset into the leaf's own content, so rewriting the field to `main.keywords` yields a payload that typechecks and mis-addresses. A step the schema does not declare is a `target-unknown`, whatever the tree happens to hold.

**The walk carries a place, not a focus**, and what a place means at its end is the leaf's — the same reason a control owns its focus. A prose leaf, a row or a cell, takes the offset (`ProseValue.setCaret`, `createField`'s body over the view it owns); a collapsed `object` row opens and hands the rest of the walk to the subform it opened, one flush later, since that subform does not exist until the row has rendered — opening is part of the landing rather than something the user does first, a collapsed row holding no control for a caret to sit in; a scalar cell takes the bare focus, an offset being a position in rendered content and a control having no coordinate to spend one in. An absent `pos` is the placement rung on this lane exactly as on `Landing`, which is where a `'segment'` hit lands, so one rule covers both lanes. The landing is therefore the one thing on the surface that answers after a flush, and `setCaret` was already async for the reveal.

**The wash marks what the address named** (`core/bloom.ts`). A landing at depth blooms the innermost row it opened and not the repeater around it: the arrival answers "here" for a click made in the other pane, and a box wider than the one the click resolved says the field where the pick said the row. So the walk hands its row back with the landing, and the registry's own box — the whole list, a field-level subform — is what a landing on the field, or on a property no row holds, falls to, along with a row the document has since dropped. Every other control is one box, which is the one the registry holds.

## Settled and open

- **Card-instance identity is a session key**: an in-memory id per card, reordered in lockstep with the content and resolved to an index only at the mutation boundary (`structure.ts` `IdSeq`). Identity is the editor's, not the document's: nothing document-side backs it, and it does not survive a reload. It rides every card-naming payload (§"The address is the spine"), so the reorder trap is a host's to fall into only by ignoring it.
- **Layout is `ui`-driven**: `ui.group` sections, `ui.compact` packs a shared row (`structure.ts`); the editor adds no responsive policy of its own beyond the container query that steps capacity (§"Structure mirrors the schema").
- **Reorder is buttons in the card stack and on an `object` row, and drag in the table island**, and the split is what each one costs. A card is a heavyweight block in a short curated set, and ↑/↓ already say everything a drag would; a record of four cells is the same case one rung in, and takes the same pair with Alt+↑/↓ as its twin; a scalar list earns neither (§"Structure mirrors the schema"). A table's lines are many, small, and ordered by the eye, so the pointer is the gesture that fits, and the drop target is the line under it rather than a zone to invent. Every one carries a keyboard twin over the same op, which is what keeps drag an accelerator instead of the only door. A drag on a row is an accelerator over the same splice and lands later, if at all.
- **Undo is per-leaf**: each prose leaf carries its own PM history. A document-level undo spanning a structural op plus a prose edit (a coordinating stack above the leaves) does not ship in V1. At depth that means removing a nested row takes its subtree with it and nothing undoes it, on one click of a slab whose keyboard twin already guards against the accidental press.
- **Array/table convergence** is `ui.layout: table`: an `array`-of-`object` of short cells draws as a grid when the quill asks, and as the record list otherwise (§"Structure mirrors the schema"). How far the grid should converge with the richtext table island (a scalar array field vs a body island, similar affordance) is not carried: the two share no DOM, and the table's rows carry the record list's controls rather than the island's grips.
- **Structural keymap**: Enter-at-end-of-body to add a card, Tab between fields: navigation crossing leaf boundaries no single PM keymap owns. Does not ship in V1; it lands as a shell keymap over `activeAddr`, alongside the insert surface. Tab is already taken inside a body (§Chrome), so field navigation reaches the inline/plaintext leaves and the body's unhandled Tab; what a body's keyboard exit should be (Escape blurs to the shell is the candidate, and it contends with the format popover's close and the card rename's revert) settles here rather than in the leaf.
- **A code block's `lang` is minted by a paste and by no other gesture**: it is carried at every rung — the info string through `importMarkdown`, the line kind, the PM attribute, `data-lang` across the DOM a copy and a paste run through (CODEC §"Markdown at the edges") — and survives an edit anywhere in the field. A `<pre>` that states a language arrives carrying it, so a fence copied off a highlighted page is authored the way every other paste is. The keyboard reaches it at neither door: the fence shorthand fires on the third backtick, before a language could be typed, and a slash command is one kebab-case token, so `code-rust` is not the shape either. Nor does the leaf draw one — `prose.css` reads no `data-lang`, a leaf showing *that* a span is code and never a prediction of what paper sets it at, though the attribute is on the DOM for a host that wants a label. That is `heading.level`'s position exactly, where the ramp is drawn no more than the language is, and both rest there while the value is only ever what a quill makes of it: the reference quill sets `raw` and reads no language, so a keystroke of its own is worth spending when a quill highlights and not before. What it would cost then is the shorthand firing on the newline rather than the third backtick, which changes when the fence appears; or a control on the block, the first attribute-level chrome in a leaf, answering for the heading's ramp in the same breath.
- **Reach the surface declines**: a per-`ControlKind` slot past the dials (the package owns reconciliation, so a slot handing out a raw `value` reintroduces a caret reset in consumer code, invisibly to this repo's tests); a pointer-only door onto the insert picks beside the slash menu; image and figure authoring, which needs an asset story the editor does not have; and the touch accessory bar the remaining mark shortcuts (`strike` / `code` / `link`) land with.
